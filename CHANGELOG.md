# Changelog

## Unreleased

- [Composer caret](<docs/NATIVE-UI-PARITY.md>): the slash menu no longer takes typing away. The blocks above the composer card were siblings in one column, so opening the menu moved the card to a new index where Iced rebuilt its subtree and dropped the editor's focus; they now share one always-present slot, which is pixel-identical while empty. Two stand-in widget tests pin both the old loss and the fix, and a real window shows `/pl` typed with the menu open and the caret still in the card.

- [Transcript selection](<docs/NATIVE-UI-PARITY.md>): dragging over a message's rendered text selects the dragged bytes with a FOAM tint, Ctrl+C copies exactly them, and the existing paste path puts them in the composer; reaching into the composer or switching sessions clears the selection. Character-precise work inside one text block (a phrase, line or code block per gesture), with block numbering keyed to the row so it survives virtualized scrolling. Six app tests cover routing, the run split and numbering; the real release binary was verified with a synthetic drag, `wl-paste`, and a paste back. Tables, tool bodies, the Details panel and cross-block selection remain unselectable.

- [Bubble line box](<docs/NATIVE-CHAT-GEOMETRY.md#the-bubble-draws-a-22px-line-round-502>): the user bubble now measures and draws the reference's own 22px line (`MessageItem.module.css:38`) instead of the shared 24px body box — a measured 2px-per-line defect, found once `reference.png` landed (the user's capture was already on disk and hash-verified). A single-line bubble is the sheet's 42px, a two-line bubble measures 64px, and the reference's four-line bubble is 108. `design::BUBBLE_LINE`/`bubble_line`, the geometry floor and cap, and the rendered `plain_view` line move together; one new test pins the contract and three expectations that encoded 24 now name the bubble's line.

- [UI wiring audit fixes](<docs/NATIVE-UI-PARITY.md>): three silent states are closed. The plan chip's in-flight flag could never clear because the reply was matched against a toggle recomputed from the projection the command itself changes; it now matches the two lines the chip can send while pending. A refused permission-default write now reaches the status instead of only clearing the saving flag, and failed permission-catalog / agent-roster / permission-settings reads are reported instead of silently presenting fallback data. Two App tests pin both.

- [Worker audit fixes](<docs/NATIVE-UI-PARITY.md>): five hops between documented behavior and the live worker loop are closed. A subagent transcript's jobs list now follows its displayed child session instead of the absent export target; job-panel failures publish a job-scoped error that no longer clears `follow_ready` and disables Send; queue edits/removals and job kills join the mutation fence; a `/permission <preset>` reply (success or refusal) reaches the status instead of being dropped; and a session-follow loss clears the jobs list and job-output streams with the selected stream. Four tests pin the child-session scope, the fence, the job-error scope and the permission reply.

- [Permission settings bridge](<docs/NATIVE-LIVE-VERIFICATION.md>): the Core gate fix exposed a second layer. `ctx.settings.describe()` answers an array of namespace views with writability on the service, while the BFF wraps both into `{writable,namespaces}`; the bridge assumed the wrapper and required a stored `defaultPreset`, which a fresh Host leaves empty because the field is volatile. It now finds `ns === 'permission'` like the reference client, reads the service's writable flag and falls back to the catalog default. A temporary Core probe against the real fork then returned catalog 3 options, settings workspace-write / revision 0 / writable, 4 presets and a same-value default write acknowledged; the probe was deleted.

- [Core permission and preset replies](<docs/NATIVE-UI-PARITY.md>): a Core audit found that `permission-catalog`, `permission-set`, `permission-settings`, `permission-default-set` and `agent-presets` were decoded by `public_result` but absent from `matches_reply`, so every reply became `Error::Protocol` and the permission chip catalog, agent-preset roster/seat and new-session permission descriptor failed silently against the real Host. The gate now matches each reply to its own command; unit tests cover the five pairs and an end-to-end Core test drives a fake supervisor for all five (verified to fail with the arms removed). Core grows from 112 to 115 tests. The same audit corrected the close-timing doc: the Core logs no shutdown phases, so the measurement needs an external timer.

- [Preset and job-resume wires](<docs/NATIVE-LIVE-VERIFICATION.md>): a read-only transport audit against the generated descriptors found two undocumented divergences. `agentPresets/select` was wrapped in a `request` body although the Host takes flat `agentId` and `agentPreset` — confirmed live: the wrapped body was refused with `gateway/arguments-invalid`, so every preset pick failed. `job/follow` sent its resume cursor as `offset`; the wire field is `from`, and the unknown key was silently ignored, so a resume restarted at the oldest byte. Both are fixed and pinned by fake-wire envelope tests (transport 84 to 86), and an App test covers the preset pick dispatch and its reply tracking.

- [All-targets fixture repair](<docs/VERIFICATION.md>): `--suite clippy` compiles every app target, and twelve fixture examples had drifted from the App's shared module set (`crash_log`, `goal_ui`, `keybindings`, `queue_dock`, `queue_update`, `single_instance`), so the clippy gate failed on unresolved imports rather than lint findings. All twelve now mirror `layout_smoke`; the geometry probe wraps `ui.rs` and re-exports only the cache it drives, with its two calls updated to the current signature. The suite passes all three checks, and the docs now record that the 2026-10-11 "App 0" `-D warnings` figure is historical.

- [Chooser reply validation](<docs/NATIVE-LIVE-VERIFICATION.md>): `directoryPicker/pick` now has a fake-wire test. It takes no arguments and answers one absolute path or `null` on cancel; missing, blank, non-string and oversized replies are refused as malformed rather than treated as a cancel. The native chooser remains unreachable on the app's browse-composed Host; this pins the contract the fallback falls back from.

- [Scroll fixture repair](<docs/NATIVE-APP-SCROLL-INTEGRATION.md>): the `scroll_app_smoke` example had drifted from the App's module set (`crash_log`, `goal_ui`, `keybindings`, `queue_dock`, `queue_update` missing), so the suite's scroll gate failed with 82 compile errors before running anything. Its includes now mirror the shared App modules; the example compiles and runs 1214 passed / 1 ignored. Only `wayland-drops` remains red, on a missing offline crate cache entry rather than source.

- [Workspace picker fallback](<docs/NATIVE-LIVE-VERIFICATION.md>): **Browse…** now learns which directory-picker capability the Host composed. Core clears `DISPLAY`, so the app's own Host serves the browse picker and `directoryPicker/pick` answers unavailable; the first failed pick states the error and opens the in-app folder list for the typed path (or the Host home), a successful listing also marks browse, and later presses go straight to the list with no repeated chooser call. A successful pick or cancel keeps the native path. App-tested; the sheet's drawing is unchanged.

- [Live Host verification](<docs/NATIVE-LIVE-VERIFICATION.md>): the alpha Host was booted exactly as the app boots it (desktop profile, isolated cleared environment) and the `@`, feedback, schedule, workspace and picker calls were driven through the real ClientRPC wire. The pass found three request defects, fixed in `c9dd30e`: a plain feedback rating sent `note`/`category` as `null`, `schedule/history` sent `before` as `null` on its first page, and the root directory listing sent `path` as `null`; the Host rejects a present null for all three. Each absent field is now an omitted key, the fake wire rejects a present null, and one transport test covers both shapes. The pass also showed that Core's cleared environment makes the Host serve the **browse** picker, so `directoryPicker/pick` is unavailable in the app's own composition and the in-app folder list is the usable path. A second pass drove the remaining non-model commands (admission, queue, goals, attachment, terminal reads, registry, model selection, cancel, `/plan`) and found no wire divergence. No schedule task or assistant message was created, no desktop file was opened and no OAuth or model request ran.

- [MCP server management](<docs/NATIVE-MCP.md>): **More → MCP servers** lists, adds, edits and disables the `@deepseek-ai/dsh-mcp-client` rows the app composes for itself. It writes one app-owned patch file inside the private native home — the Host's home-level layer, composed above the profile's own `cordis.patch.yml` and below `--patch` overlays — one loader entry per server, rendered whole, re-parsed and compared before an atomic `O_EXCL`+rename replacement, with a timestamped mode-0600 backup of the previous file. Add, edit and remove each require Review → Confirm; remove sets `disabled: true` and keeps the entry and its configuration; environment and header values are restated byte-for-byte but never rendered; and content outside the app's canonical form fails closed with its offending line rather than being rewritten. An admitted write shares the single management flight with registry, rename, fork, terminal and export mutations. Unit-, worker- and App-tested (42 new tests) against real files and real transport types; no live Host or MCP server was connected, so row resolution, mounting and a real `tools/list` are unqualified, and because the native Core does not start the Host with `--expose-internals` the Host's config watcher cannot run — a written change mounts after the app is restarted, which the panel states rather than implying a hot reload.

- [Context health, context management and the loop guard](<docs/NATIVE-CONTEXT-HEALTH.md>): the composer's context line is tiered against the mounted compaction threshold and states the window limit instead of only tinting it; Trajectory gains quiet single-line `Context elided`, `Context summarized` and `Compaction failed` rows plus a labelled `Loop guard · bash × 8` reminder, while the `compaction/start`/`end` brackets produce no row; the newest `todo/write` becomes one muted plan chip, and the Host's `plan` projection becomes a read-only accent indicator that distinguishes an active mode from a selection still waiting to be appended. Chat stays clean: exclusion is now decided by the event kind before any display label, which fixes `session-log-deepseek/delivery-accepted` and the system prompt both rendering as JSON in the conversation, and an invariant test pins the whole known vocabulary. Unit-, fixture- and App-tested with five inspected render frames; no live Host or provider ran, so real compaction traffic and a live loop-guard reminder are unqualified. Findings applied from [arXiv:2609.20804](https://arxiv.org/abs/2609.20804).

- [Desktop notifications](<docs/NATIVE-CONTEXT-HEALTH.md>): a turn that settles while the window is unfocused raises one `notify-send` notification, and a broken update stream raises the other. Only a falling edge of the Host's own run flag announces, never a session first seen already running, never while focused, and never in a smoke run; every field is a separate argument and the child is spawned, not waited on. Unit-tested over the transition rules; no live desktop delivery was observed.

- [Slash-command completion](<docs/NATIVE-CONTEXT-HEALTH.md>): a leading `/` in the composer opens a menu of the commands the Host advertises, with prefix-first matching, wrapping `↑`/`↓`, `Tab`/`Enter` to accept and `Esc` to dismiss. Accepting rewrites the draft and never executes, the menu closes once the line leaves the command position, and the advertisement is read lazily on the first slash. A published `plan` projection now renders a pressable chip that sends the Host's own `/plan` or `/plan off`, asking for the opposite of the committed state. Unit-, fixture- and App-tested with an inspected frame; no live Host ran, so the real advertisement and the gateway's reply to `commands/execute` are unqualified.

- [Multiple attachments](<docs/NATIVE-ATTACHMENT-UX.md>): up to four files at 4 MiB each are owned at once, each with its own review, upload and Remove, and one Send binds every ready file into a single prompt whose exact ticket set the worker releases on settlement. A bounded manager reuses the unchanged per-file draft machine and continues its serial high-water marks, so a second file can never mint a duplicate ticket or editor stamp. Wire-verified by unit tests; a rendered multi-file frame and a live two-file Host run are not yet qualified.

- [Session rename](<docs/NATIVE-REGISTRY-CONTROLS.md>): the per-row options gain **Rename…**, a compact editor pre-filled with the visible title. Local validation refuses blank, over-1024-UTF-8-byte and control-character titles while keeping the typed text; Review → Confirm sends one `session/rename` (`{sessionId,title}` → `{title,seq}`), the sidebar applies only the Host-normalized ACK, and a stale/foreign receipt or unknown outcome changes nothing and never retries. Unit-, fixture- and App-tested; no live Host rename was executed, so real normalization and the durable `seq` are unqualified.

- [Session fork](<docs/NATIVE-REGISTRY-CONTROLS.md>): the per-row options gain **Fork…**, an explicit Review → Confirm that sends one `session/fork` (`{sessionId,atSeq?}` → `{sessionId}`) for the latest completed-turn prefix. The child id is authoritative only from the ACK; the child is selected only when the App's own roster or follow frames already contain it, an unseen child is reported with its id and left unselected (no invented row), a fork in flight shares the single management/rename/export flight, and `fork-unavailable`, created-but-unattached and unknown outcomes stay distinct, indeterminate where needed, and never retried. Unit-, fixture- and App-tested; no live Host fork was executed, so real seeding/attachment and the durable child id are unqualified.

- [Read-only work panel](<docs/NATIVE-WORK-PANEL.md>): **More → Work records** projects the retained `goal/change`, `todo/write`, `subagent/catalog`/`subagent/descriptor` and `schedule/change` events into four compact sections, bounded to 50 records per section and 200 total with every omission stated. It adds no command, effect, prompt or schedule-goal-subagent authority; malformed payloads contribute nothing and unknown kinds stay in Trajectory. Unit- and fixture-tested against synthetic records; no live Host session has been exercised, so real field shapes and Host-side freshness are unqualified.

- [Host terminal panel](<docs/NATIVE-TERMINAL.md>): **More → Terminal** is a client-only view of the Host's `terminal/*` service. The app never spawns a shell: opening reads `terminal/list`, `terminal/shells` and `terminal/environment`, selecting attaches one `terminal/follow` with exclusive input control, and create/close/write are explicit Review → Confirm actions with owned-ticket/epoch fencing that share the single management flight with rename/fork/export. Output is sanitized and bounded (400 chunks / 128 KiB retained, 32 KiB rendered) with discarded output counted; create/close add or remove nothing before the Host ACK and unknown outcomes stay indeterminate without retry. Transport is fake-wire- and App-tested; no live Host terminal was created, attached or closed, so real shell discovery, PTY behavior and stream framing are unqualified.

## 2026.10.10-r1 — Native Linux development release

October 10, 2026, America/Chicago. Calendar versions use `year.month.day-rN`; `N` is the release number for that day. This release collects the current frontend, Core, transport and companion-backend changes—not only the last Settings fix. [Release checks and limits](<RELEASES/2026.10.10-r1.md>).

### Settings and Codex

- Centered Settings with Account, Models & runtime, Images and Maintenance tabs, an inactive background and visible consent/error/cancellation status.
- Managed local account roster, Add, epoch-checked Switch, local Sign out and Sign out all. Explicit Review → Confirm; stale callbacks, unknown outcomes, selected-account Switch and empty-All guards. Interrupted sign-in invalidates cached roster controls until fresh owned readback. Add does not automatically select an account; Connect follows only its own exact added-account receipt. No legacy grant import.
- Eight runtime/image-input preferences: transport, cache retention, request/connect/idle timeouts and image pixel/per-file/total byte budgets. Revision-checked Refresh/Save, local Reset drafts, inherited/effective/override distinctions and explicit reconciliation after uncertain saves.
- Revisioned private usage preferences with bounded admission, cooperative flock and atomic writes. Supported local opt-outs persist; unavailable opt-ins stay disabled and owner-rejected. Quota/app-server/reset-policy foundations remain experimental and unwired, not live quota support.

### Models and composer

- Anchored provider/model, reasoning, service-tier and output-detail menus with responsive Back/toggle/outside-click behavior and owned acknowledgement before selection.
- Advertised provider-backed priority processing and verbosity controls; default omits overrides. Priority is a premium request, not a speed or entitlement guarantee.
- Startup active-model read and automatic startup/picker catalog refresh. Global read tickets reject stale, duplicate and unsolicited results; loading/offline/applying labels reflect actual state. Welcome selection can create a conversation without prompting.
- Enter/Ctrl+Enter send non-whitespace text; Shift+Enter inserts a newline. File-only Send remains explicit.

### Attachments and drafts

- Native in-window file picker, bounded asynchronous browsing, local PNG/JPEG previews and one-slot attachment ownership. Selection/drop stays local; Upload and Send are separate explicit actions. Remove/Cancel does not roll back remote storage.
- Pinned winit 0.30.13 Wayland source patch: bounded single-local-file URI drops on the existing owned queue, COPY-only admission, dispatch/deadline/seat/window limits and visible rejection/Attach fallback. Preserve Apache-2.0 notices, upstream pins and bundled SVG CC-BY-SA attribution.
- Private plaintext per-session drafts, bounded/coalesced persistence, explicit recovery review and Reload after uncertain failures. Separate original Send ownership from newer editor revisions; late acknowledgements retire only original ownership. Exit joins admitted picker/preview/draft filesystem work.

### Conversation and navigation

- Native Markdown/code rendering, modest lexical highlighting, collapsible supplied thoughts, Copy/code Copy and explicit text-only Edit-to-draft. Unsupported markup stays literal; links stay inert. No hidden-reasoning request or Regenerate replay.
- Ctrl+F search of the loaded conversation with native prose/code/thought highlights, navigation and scroll geometry; no implied remote search or older-page fetch.
- Keep Host-confirmed queued input visible through preparation, correlate durable user messages by identity, preserve append-origin conversation across context rewrites and avoid duplicated streamed/durable answers.
- Surface preparation, interruption and output-limit failures. Suppress credential-bearing auth diagnostics and title/model-control events from chat; retain raw records and older/reload actions for empty paginated views.
- Validated context-pressure/last-request usage and Host-owned Working indicators with focus/animation gates. Bound navigation to 200 matching sessions without duplicating the complete session list.

### Delivery, transport and teardown

- Freeze original Send identity/payload/file ownership after acknowledgement uncertainty. Read-only Check submission uses typed prompt-admission evidence; unknown/malformed/missing observations never authorize resend. Admission is not provider completion.
- Explicit observation rejoin requires correlated original-pipe proof from the same owned Host and cached transport. No reauthentication/restart, automatic session follow/resume or mutation replay.
- Reserved Stop admission independent of ordinary worker/transport capacity. Cancellation preserves queued input; its acknowledgement does not mean idle.
- Immediate transport revocation on private-pipe EOF/protocol fault. Retry only wholly unwritten shutdown frames within the original grace deadline; never replay partial/poisoned frames or call an already-exited root forced.
- Incremental decoded UTF-8 framing accounting and validated WebSocket payload ownership transfer without cloning; retain authentication, correlation, envelope and queue guards.

### Companion backend

- Opt-in managed Codex vault/owner with private permissions, lifetime POSIX flock, atomic recovery, optimistic selection epochs, immutable account/epoch SDK bindings and drainage before switching/deletion. Ordinary profiles retain legacy behavior; account service stays Host-only and value-free.
- Explicit request controls through LLM, defaults, Session Controller, TS/Python SDKs, ACP, subagents and replay. Exact supported endpoint/model allowlist; reject unsupported controls before credentials/provider I/O. Omission preserves defaults; route changes clear overrides.
- Payload-correct bounded prompt-admission ledger: reserve before asynchronous intake, identical concurrent requests join, changed payload conflicts, predecessor missing digest stays unverifiable. Nonactivating status and historical Inbox evidence cover receipt-loss gaps; no automatic resend.
- Immutable forwarded Remote event snapshots with separate source/client/pending count and UTF-8 byte budgets and explicit overflow errors; lifecycle cleanup and one-argument source-factory compatibility retained.
- Lazy optional-browser HMR polling: no recurring bundle scans without SSE consumers, catch-up before opening, one shared poller and silent stale callbacks/disposal. Web composition remains available.
- Focused negative/lifecycle/Loader tests, current-v4 request-control SDK/session/Python recordings, bilingual catalogs, type-equivalence and persistence acknowledgements, and upgrade guides. [Companion changelog](https://github.com/IOUJared/deepseek-harness-linux/blob/v2026.10.10-r1/CHANGELOG-NATIVE.md).

### Verification and distribution

- Risk-based verification skills/instructions, serial two-job locked/offline runner, doctor/lint/example suites, selected Rust safety checks, source-drift detection and retained failures.
- Expanded production reducer, worker, parser, fake-wire and storage tests; PUBLIC composed account/runtime/usage/file/draft and isolated native-seat/drop/interruption tooling. These owners do not imply a combined physical-input/live-provider certificate.
- Frozen source/binary selection, one bounded source copy/inventory/overlap policy including App vendor sources, exact extraction checks, explicit missing UI-certificate status and qualified external-runtime launcher. Source hashes are consistency—not compiler ancestry, signatures or reproducibility.
- Release verification fixes branded Settings event fixtures, regenerated Cordis API metadata, dispatch JSDoc and the pinned winit locale filter's Rust 1.99 lint compatibility. Preserve historical Session recordings; current admission-aware Web replay has its own fixture owner.
- Calendar native crate/archive/tag identity; explicit calendar publication prevents CI from racing verified assets. Legacy plain-version `dev.run` automation remains separate. Native-only CI explicitly reports companion-artifact tests as skipped; strict companion-artifact runs must fail if prerequisites are absent.

### Compatibility and unfinished work

- Exact rebuilt alpha backend `0.2.1-alpha.1`, Node 26, Python 3.11+ tooling and Linux/Wayland/system fonts/GPU libraries required. Backend SDK version remains unchanged; calendar tags are GitHub release identities, not npm/PyPI releases. Installed RC is incompatible.
- Pre-stable public enums, model selection/catalog and request fields require matching rebuilt consumers. Session format remains v4 and SQLite version unchanged; predecessor generations are preserved.
- No live OAuth/provider, verified subscription quota/reset/alerts/retry, image generation/sketch, physical mouse/keyboard/IME, accessibility, adversarial-containment or power-loss certificate. Local sign-out is not issuer revocation; metadata/catalog is not entitlement.
- One attachment/4 MiB intake, bounded PNG/JPEG previews—not a resource sandbox. MOVE-negotiated file-manager drops may be rejected; Attach is the fallback. Drafts/vaults are private local plaintext, not encryption or legacy migration.
- Not standalone/installer/AppImage/update service, general Linux portability, Windows/macOS parity, clean-machine packaging or complete redistribution-license certification. No new performance ranking or long-chat benchmark claim. Private evidence, profiles, tokens and screenshots are excluded from GitHub source.
