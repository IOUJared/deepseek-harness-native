# Native Harness UI comparison

Status: prototypes, not a complete Harness app. Compare Slint 1.18.1 and Iced 0.14.0, verified against crates.io on 2026-10-06. No Electron, Tauri, browser engine, real Harness process, account credentials, network/model calls, or normal user data in either prototype. Backend integration and full-app memory are separate measurements.

## Common screen

- Initial logical window 1200×800; resize supported; sidebar width 260, header height 48, composer height 104, transcript fills remaining viewport.
- Standard dark Rosé Pine: base #191724, surface #1f1d2e, overlay #26233a, text #e0def4, muted #6e6a86, subtle #908caa, accent #c4a7e7, border #403d52. No desktop/theme changes.
- Default sans-serif text at 14 logical pixels. Match actual font family and report any fallback.
- Sidebar shows product title, three fake workspaces, twelve fake session titles, and Settings. Buttons select a fake session. Composer accepts text, Send appends a fake user message, Stop cancels only synthetic streaming, never launches a model.
- Initialize exactly 1,000 fixed-height (72 logical pixel) transcript rows. Row i has role `You` when i % 3 == 0, otherwise `Assistant`; body `Message {i}: Review the workspace and keep changes small and tested.`; footer `Tool result: completed` when i % 5 == 0, otherwise `Synthetic benchmark transcript`. All row heights include their padding/borders. Virtualize visible rows plus small overscan; do not construct all row widgets every paint. Retain full message data.

## Execution and protocol

- Standalone Cargo package per prototype, release optimization identical: opt-level=3, thin LTO, codegen-units=1, strip symbols. Versions pinned exactly. Disable framework defaults, explicitly select Wayland and available software/GPU renderers. Do not compile Qt or Skia unless a documented renderer reason requires it.
- CLI `--bench` runs bounded phases; without it normal interactive prototype stays open. No settings, state, or source files are written by the app unless an explicit output path is passed.
- Print newline JSON prefixed `DSH_BENCH:`. Each event includes `framework`, `event`, `elapsed_ms` from entry to main. Events: `initialized`, `ready`, `idle_start`, `scroll_start`, `scroll_end`, `stream_start`, `stream_end`, `finished`. `ready` includes a precise `measurement` label, renderer, logical size, and effective scale. A supplemental one-shot `settled_geometry` at ready+750ms reports the actual UI viewport; it requests no redraw and resets no phases. Require independent owned-PID compositor mapping and correct 1200×800 logical geometry before ranking. On this native-scale-1 desktop, scale 1.25 must produce a 1500×1000 physical viewport, not a smaller UI or double-scaled window. Iced labels physical size derived from queried viewport/effective scale; compositor facts remain independent evidence. Never call a redraw request a presented frame.
- Bounded bench schedule relative to `ready`: initial idle 6 seconds, scrolling 6 seconds, streaming 6 seconds, final idle 4 seconds, then clean exit. Emit `idle_start` at ready. Scrolling advances the transcript by 72 pixels every 16 milliseconds, bouncing at boundaries. Streaming updates the last visible message every 50 milliseconds; content grows by the same ` token` text fragment. No repeating timers or redraw loops remain during idle. End-of-phase timers are one-shot. A manual close cancels pending timers and exits.
- Include counts and elapsed phase time. Frame or submission intervals are useful only with an honest instrumentation label and no observer-induced redraw loop. First-frame and startup proxies must stay explicitly distinguishable. The parent runner records spawn-to-ready, OS mapping, CPU deltas, RSS/PSS including child processes, available DRM VRAM, system load averages, renderer environment, renderer-reported timings, and binary size. The analyzer derives phase ranges from event timestamps, distinguishing a supplemental final `idle_start` from the first idle period; it excludes the first 1.5 seconds of initial settling and 750ms at other phase boundaries. CPU percentages use one logical core, not whole-machine percentages; both medians and means are reported. Null PSS/VRAM remain unknown, never zero.
- Renderer variants: Slint winit software and FemtoVG/OpenGL; Iced tiny-skia and wgpu if supported. Software is not automatically faster. Same release flags, fonts, content, geometry, duration, scale, and background-load recording.

## Wayland, scaling, safety and evidence

Force native Wayland only in the test child environment by removing DISPLAY and retaining WAYLAND_DISPLAY. Verify actual backend, not only a requested environment variable. Do not change monitor configuration, refresh, VRR, focus rules, desktop theme, launcher, or compositor scale. Test current display scale and optional application-controlled 1.25 UI scale; mark compositor fractional scaling untested unless already present and exercised.

Run graphical tests through approved desktop access with isolated XDG homes. Only own test PIDs/process groups may be stopped; no broad process name matching. Snapshot only internally rendered synthetic app content, never other windows or whole desktop. Measurements must distinguish frontend prototypes from the integrated app and describe missing hardware/compositor presentation evidence. Slint distribution licensing must be reviewed before selecting it for release; Iced is MIT. No license option is silently accepted on the user's behalf.
