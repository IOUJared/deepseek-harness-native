# Native Host lifecycle foundation

MIT-licensed Rust 2024 library, version 0.1.0. **Foundation, not a finished app.** No GUI, Electron, webview, Slint, Iced, crate SDK, or model-engine dependency. The selected native toolkit can consume this library later without changing Host ownership. The optional `transport` feature composes the [authenticated Rust HTTP/WS client](../transport/README.md) inside the private ownership boundary. DeepSeek account mutation is not implemented. Explicit native Codex OAuth uses the same-version isolated authorization flow; it is not executed by opening Settings or starting Core.

## Start / control / event / stop API

[Backend](<src/lib.rs>) owns the private Node Host. `Backend::start(RustBackendOptions)` returns the native-only handle and a bounded `mpsc::Receiver<PublicEvent>`. `wait_ready()` waits for authenticated readiness. `request(Command, timeout)` performs a bounded control write and waits for a typed `PublicReply`. `stop_async()` queues teardown and returns a completion receiver without blocking the UI. `stop()` is the blocking worker variant and joins its monitor and output-reader threads. Dropping the handle queues teardown; an application should keep its worker alive until the stop result is observed before exiting.

Run start, readiness, control requests, and synchronous stop on application workers, never the UI event loop. Widgets receive only `PublicEvent` / `PublicReply` / metadata. Event buffering is capped at 128; delivery never blocks the reader, and `dropped_event_count()` reports discarded events. In-flight requests are capped at 128. An unknown `Inspection` is a warning, not idle: call `is_known_idle()`, and treat request errors as unknown activity.

Account observation is [explicit opt-in native work](<../docs/NATIVE-LAZY-ACCOUNT.md>); startup retains the required service binding without a watch or Platform-session mirror. `AccountSubscribe` activates one owned watch, `AccountUnsubscribe` retires it, and provider loss requires explicit resubscription. One-shot onboarding/account reads remain independent; ending observation never cancels or confirms an admitted write.

The closed nonsecret command enum provides inspect, open_workspace, onboarding_read, account_state, account subscription/unsubscription, and cancel_generation. With `transport`, [registered-Agent discovery](<../docs/NATIVE-AGENT-DISCOVERY.md>) adds `DiscoverSessionAgent(SessionId)` and a typed `AgentDiscovery` reply: exact registered object ID or explicit absence, never an inferred ID, Agent activation or retained lease. The development SDK adds enum variants; exhaustive consumers must update. Explicit API-key persistence uses the separate consuming `save_api_key(SecretApiKey, timeout)` native-worker operation below; Command never holds a naked secret string. Shutdown is owned by stop, not an arbitrary JSON request. There is no public JSON service-invocation entry, DeepSeek account-start/signout, arbitrary settings write, API-key read/getter, or generic browser/desktop control. Fixed Codex status/start/cancel and revision-checked provider activation are separate explicit controls.

[Validated options](<src/options.rs>) require an absolute built fork runtime directory, exact expected version `0.2.1-alpha.1`, explicit caller-owned native home, user home, working directory, startup timeout (1ns–30s), and bounded stop policy (each phase 1ns–10s). The runtime manifest must identify `@deepseek-ai/dsh` at that exact version. There is no installed-runtime fallback. None for the optional absolute Node path selects `/usr/bin/node`, never a working-directory executable or ambient PATH search. Caller-selected Node paths must resolve to executable regular files. Native-home defaults belong to the future application configuration layer; this library deliberately has no default.

Child environment is cleared, then only explicit HOME, fixed `/usr/bin:/bin` PATH, DSH_TAURI_HOME, DSH_TAURI_RUNTIME, DSH_TAURI_EXPECTED_VERSION, and telemetry-disabled values are set. Ambient credentials, NODE_OPTIONS, GUI environment, and runtime overrides are not forwarded. Inherited DSH_HOME is used only as an additional forbidden home alias; it is not a runtime/home fallback. Canonical home validation excludes legacy `~/.dsh`, its descendants/ancestors and symlink aliases, plus invalid caller roots; the stable adapter independently repeats its isolation checks.

## Privacy and bounded I/O

[Private parser](<src/protocol.rs>) retains authenticated launch URL/origin and Platform origin/token/request headers only in private state. Private Ready/Auth events and credential structs have **no Debug, Display, or serde projection**. The handle likewise has no Debug/Display/serde implementation. Native-only borrowed accessors remain `pub(crate)`, never exported renderer callbacks. With feature `transport`, `connect_transport(Limits).await` privately constructs the launch capability exactly once after readiness, without holding the state mutex across network I/O. It rejects competing/repeated initialization and checks Host liveness again before registering the client. The Core retains a private client clone and synchronously invalidates all transport clones on explicit stop, Drop, automatic monitor fault/disconnection teardown and observed root exit. The same owner cancellation token drops a pending private authentication exchange immediately instead of waiting for its network deadline. Failed authentication requires a new Host owner rather than replaying a guessed capability. Secrets are discarded on root exit/teardown. No token-bearing raw Value or session object enters a public event or reply.

Public account metadata is an allowlist of status and attempt-phase enums. Onboarding exposes three booleans. Account links, authorization URL, attempt/user IDs, tokenValue, unknown fields, and free-form text are excluded. Readiness exposes only the checked runtime version. Launch URL validation accepts only an authenticated HTTP 127.0.0.1 root with a nonzero explicit port and exactly one nonempty token query parameter, without userinfo or fragment.

Stdin frames, including newline, are at most 65,536 bytes. Nonblocking writes have a 500ms deadline and a try-lock writer; partial/time-out/closed writes poison framing and trigger owned teardown. Replies wait for an explicit timeout of at most 30s. Stdout lines, including newline, are at most 65,536 bytes, with bounded buffering and no splitting of oversized data. Unknown framed events and unframed data are discarded; malformed recognized packets, oversized/unterminated lines, and early stdout EOF fail closed. Child stderr goes directly to null: arbitrary Host diagnostics, exceptions, secrets, and stacks are never logged by Rust.

## Explicit native-worker API-key persistence

[SecretApiKey](<src/secret.rs>) consumes `String` input through `SecretApiKey::new(raw) -> Result<SecretApiKey, Error>`. Input must contain 1–16,384 printable non-whitespace ASCII bytes, matching the stable private adapter's command parser; whitespace, empty input, non-ASCII/control bytes and oversize input are rejected with a fixed `InvalidCommand`, never echoed. Debug is always `SecretApiKey([REDACTED])`. There is no Clone, Display, serde implementation or public plaintext getter. Never put the raw input in GUI/model/event Debug, logs, JSON, CLI arguments or environment variables; callers own any copies before transferring the input to this native-worker wrapper.

`Backend::save_api_key(secret: SecretApiKey, timeout: Duration) -> Result<bool, Error>` is the official API-key secret-bearing operation. It is blocking worker work, not a UI event-loop callback, and is separate from the derived-Debug nonsecret Command enum. It validates the same readiness, stop state, request-count, 500ms writer and at-most-30s reply bounds as ordinary controls. A private borrowed field struct serializes directly into a preallocated, wiping byte frame with exactly type/requestId/apiKey fields, correct JSON escaping and a complete newline-inclusive 64KiB bound. Its writer rejects overflow before extending, so no partial secret frame is reallocated. No secret-bearing serde Value or cloned key String is constructed. No plaintext frame or key is retained in the pending map, public replies, events or errors. The only public parsed save result is `ApiKeySaved(bool)`; extra fields, free-form error text and echoed secret fields are discarded.

A true return acknowledges that the existing official-provider `credentials.set(credentialRef(ref), normalizeApiKey(value))` operation completed. False means adapter/provider refusal. A timeout or failed reply is **indeterminate**: persistence may already have completed. Re-read `request(Command::OnboardingRead, timeout)` for has_api_key/writable/logged_in metadata; presence cannot identify which key committed and must not turn a timeout into a confirmed-save result. Do not automatically retry, replay the secret, or perform a credential read. This operation does not automatically sign in, validate a key with a model/catalog request, alter Linux account infrastructure, or expose account mutation.

The stable adapter registers the key with its existing diagnostics redactor before invoking the official-provider save flow. The Rust wrapper's input allocation is wiped as soon as the encoded frame is constructed; the encoded allocation is wiped immediately after its bounded write attempt, before awaiting the reply. Both wipe on all rejection/error/drop paths using local volatile stores and a compiler fence, including spare capacity. The required offline shared cache contains no zeroize crate, so no dependency/download was introduced. This only covers the owned Rust allocations, not earlier caller/GUI copies, kernel pipe buffers, allocator/swap artifacts or Node/provider strings; it is not a locked-memory guarantee.

The API accepts no credential reference, provider namespace or destination path. Under the **trusted default isolated desktop profile**, the audited credentials-local provider persists the official reference atomically with 0600 file/0700 directory modes in the caller's explicit native home; installed Harness storage is not used. Upstream credentials-local also supports a trusted profile Config.path override. Rust cannot introspect that override over the stable closed channel and does not claim confinement against arbitrary caller-supplied runtime/profile code. Production callers must retain the audited default storage provider or separately enforce provider destination policy; neither original adapter nor fork source is modified here.

[API-key fixture tests](<src/secret_tests.rs>) use only the explicitly public fake sentinel and persist a boolean marker, never an actual credential value. They cover redacted Debug, nonserialization/non-Display compile failures, input/frame bounds and escaping, successful/refused/malformed/wrong-command acknowledgements, fixed errors, an indeterminate late commit, writer contention/partial-write deadlines, private-home marker scope, metadata refresh and no key in public events. [Validation log](<evidence/api-key-foundation-final.log>) and [result summary](<evidence/api-key-foundation-result.json>) record 46 transport-enabled and 44 transport-disabled fixture tests plus four privacy compile-fail doctests; no real key, Harness/model/catalog/account request or GUI was used for this task.

## Explicit native Codex authorization

[Codex metadata](<src/codex.rs>) is Copy, non-serde status only: availability, configured grant-record presence (not token validity), route registration, six fixed phases, local attempt/prompt serials, browser availability, settings revision and retry blocking. `Command::CodexStatus` reads local metadata; `CodexStart` explicitly starts only `authorization.begin` for `llm-pi-ai/openai-codex` and `oauth`. The [private helper](<runtime/codex.mjs>) selects only the verified browser option, never device-code login, launches no browser itself, and only accepts the installed browser flow's known manual callback prompt. Unknown interactions fail closed without forwarding text. Start acknowledges ownership without waiting for OAuth. Local snapshots capture attempt generation before awaiting credential metadata and boundedly retry/reject changes, for command replies and publication alike; an old presence result is never paired with a newer attempt phase. Opening Settings, Core startup, metadata refresh, authorization success and route activation never request a model/catalog or submit a prompt.

`SecretCodexCallback::new(String)` consumes 1–16,384 printable non-whitespace ASCII bytes without trimming. `Backend::submit_codex_callback(attempt, prompt, secret, timeout)` serializes only a private bounded wiping frame and consumes the wrapper. It returns a boolean admission receipt, not authorization success. Node owns monotonic safe-integer serials, retires prompt resolvers exactly once and fences whole-attempt and prompt withdrawal signals. Callback text, OAuth URLs and provider messages/errors never enter public replies/events, Debug, status strings or evidence. There is no public URL getter, credential read, direct token write, signout or generic authorization dispatch.

`Backend::open_codex_browser(attempt)` is explicit blocking worker work. The [private browser holder](<src/browser.rs>) validates the exact installed pi-ai HTTPS authorization origin/path and all fixed query fields, state and PKCE syntax both on reception and launch. One attempt-scoped capability can launch only `/usr/bin/xdg-open`, with null standard streams, a cleared environment and an allowlist of the native caller's desktop identity (HOME, locale, display, D-Bus and XDG/Hyprland paths), plus fixed `/usr/bin:/bin` PATH. Ambient credentials, NODE_OPTIONS and BROWSER shell overrides are never forwarded. Spawn, cancellation tombstones and stop admission share the private state lock. Valid metadata acknowledgements register attempt identity before delivery; cancelling that known attempt retires URL authority even before its first private state packet. Delayed packets cannot restore cancelled authority, and an older cancel cannot revoke a newer attempt. The worker waits at most five seconds, then requests launcher termination and retains a reaper. Success means launcher completion, not successful browser display or login. The user's browser is outside Node ownership and is not killed on cancellation; browser/launcher argv, URL parser allocations, GUI, Node and OS copies are not guaranteed erased.

`CodexCancel { attempt }`, the private fifteen-minute deadline, unsupported interaction or failed attempt blocks retry for this Backend lifetime. Cancellation may settle before an orphaned upstream flow/store commit: `retry_blocked` and indeterminate metadata do not promise absence of a later credential write. Refresh local metadata and restart the owned Backend before an explicit new attempt. Stop revokes Rust browser authority and aborts the Node attempt before Host teardown; upstream seam settlement is not proof of orphan quiescence. Owned lifecycle escalation remains the final bounded process cleanup.

`CodexEnableModels { expected_revision }` resolves the unique configurable `openai-codex` directory entry and actual settings namespace. It requires local credential presence, a writable descriptor, no active/blocked attempt and matching revision. It writes only the absent provider path as `{}` through settings path mutation/CAS; an existing profile is never overwritten, and routability is checked through `llm.listProviders`, not model requests. Generic Plugins' custom-page opt-out remains unchanged. Errors/timeouts are fixed and may be indeterminate; never automatically retry writes or infer which credential is stored. Model loading and session selection remain separate explicit application actions.

[Focused tests](<src/codex_tests.rs>) are authored with public dummy input and staged mock services only; they perform no OAuth, browser launch, credential/network/catalog request or real runtime login. Parent execution and qualification are required; authorship is not a test-pass claim.

## Linux ownership and teardown

[Ownership monitor](<src/process.rs>) spawns Node on its own persistent thread. Linux PR_SET_PDEATHSIG follows the spawning **thread**; therefore a short-lived startup worker cannot own the actual spawn. Pre-exec sets an owned process group, installs SIGTERM death notification, and checks the original parent process before exec. A fixture verifies survival when the caller's startup thread finishes and death notification when the owner process is killed.

The ownership thread polls/reaps Child independently of stdout EOF. Group signalling is allowed only while that thread still owns the unreaped root, with matching PID/group/start-time identity and a final try_wait check. After root reap, there is no killpg call: observed descendants have identity-validated Linux pidfds and are cleaned up individually. The 25 ms sampler traverses only `/proc/<owned-pid>/task/*/children` (all owned threads), never the desktop-wide PID directory. Child PPID/start-time and parent identity are fenced before capture. Already pinned live parents refresh changed group identity while preserving pidfd authority, so orphaned/reparented group-changed parents still contribute newly forked descendants. Stop waits for shutdown acknowledgement **and** successful root exit before reporting graceful. TERM/KILL escalation, bounded acknowledgement lag, observed descendant cleanup, and joined reader shutdown are separate from GUI work. Unsolicited shutdown acknowledgements cannot fake graceful completion.

Unexpected/unacknowledged exits and forced cleanup report `containment_unknown`; they never claim that an unobservable former process group is safely owned. `observed_descendants_remaining` exposes incomplete cleanup. If an uninterruptible owned process exceeds the kill wait, stop reports the incomplete result and a private reaper retains Child/pidfds for cleanup instead of abandoning ownership. This is cooperative Host lifecycle management, **not adversarial process confinement**: /proc snapshots cannot prove containment of descendants that fork, become unobserved and reparent/escape between observations. Merely changing an already observed parent's group no longer defeats descendant traversal. Strong containment across that case requires a future owned cgroup/service scope, not broad post-exit signalling. Process death may leave static staged scripts in a private temp directory; it does not write control credentials there.
