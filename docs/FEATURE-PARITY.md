## Acceptance policy

- Features are not counted complete merely because a button exists, an RPC was accepted, an authored fixture passes, or a backend capability exists.
- User decisions are explicit: no automatic approval, question reply, API-key write, model call, provider catalog, permission-policy change or account sign-in.
- Keyless fixture tests use public fake values and owned temporary homes/ports/processes. They do not read real credentials or modify the installed runtime/profile.
- A timed/continued question without its correctly owned host claim remains unsupported rather than guessing a deadline, closing a claim early or steering an answer under session-derived Agent authority.
- Lazy guest compatibility does not become a mandatory primary webview and does not receive generic privileged native execution or raw native cookie access.
- Current development API change: question methods now require `AgentId` rather than `SessionId`; consumers must obtain actual registered Agent/event authority. Wire field names are unchanged.
