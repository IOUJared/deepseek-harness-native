# Native chat features

- **Thoughts:** collapsible, separate from the answer. Only exact backend-supplied reasoning blocks; unknown formats keep the literal fallback. No hidden-reasoning request.
- **Markdown:** native headings, emphasis, lists, quotes and fenced code. Small lexical highlighting for common language labels; inert links, no images/webview/code execution. Unsupported markup stays literal. Existing 32-KiB display and parser budgets apply; stored Details preserve the bounded source.
- **Copy:** durable answer/message or exact displayed code block. Source/generation tickets reject stale actions; clipboard copies are not securely erased.
- **Selection:** drag over a message's rendered text selects the dragged bytes with a tint (FOAM at 40%, the reference's document-selection stand-in), and Ctrl+C copies exactly that text when no field owns the key. The selection is local state: it never becomes a Host command, a press in the composer or a session switch ends it, and paste into the composer uses the existing clipboard path. Clamped to one text block (a phrase, line or code block per gesture); assistant prose, headings, code and reasoning bodies share the path, while tables, tool bodies and the Details panel are not selectable. No double-click word, keyboard selection or auto-scroll while dragging.
- **Edit:** confirmed text-only user messages populate the composer. Replacing a nonempty draft requires consent. Send remains explicit and keeps existing admission guards; no conversation mutation, queue/file-receipt replay or automatic resend.
- **Usage:** approximate Host context pressure only at a validated current opening snapshot; otherwise actual last-request counters when available, or **Usage unavailable**. Never a running-state, billing, admission or Send gate.
- **Regenerate:** unsupported by this alpha BFF. Fork is a new conversation, not regeneration or tool rollback; no synthetic replay button.

- **Search:** Ctrl+F or Find; case-insensitive literal Unicode-lowercase search of loaded user/reply text and supplied thoughts. Highlights native prose/code, navigates matching messages, expands a selected user preview/thoughts and shapes the first visible match for scrolling. No older-page fetch, regex or remote request. Query ≤256 bytes, source ≤32 KiB, ≤1,024 highlights per text fragment. Long code may still need horizontal scrolling; glyphless matches fall back to the body origin.
- **Drafts:** private plaintext local draft text only, under the configured native home. Recovered text is **delivery-unknown**: it may already have been submitted before a crash. Send requires current explicit review; edits invalidate that consent. Currently owned pending originals are excluded by session/editor-revision ownership, while newer text remains eligible. Async initial read; serialized/coalesced saves approximately every 750 ms while dirty. A newer editor or matching Send-ACK removal supersedes an older save/read. Late ACKs retire the original session's editor revision, not a different session's current revision. Send waits for outstanding session creation. Staying after a startup Close resumes the initial recovery read; it never retries a failed read implicitly. Errors pause persistence; **Reload drafts** explicitly reconciles, never automatically retries an uncertain save. Closing waits for admitted filesystem IO; failed saves require an explicit unsaved exit. No queued IDs, attachment receipts, account state or automatic Send. Limits: 128 sessions, 32 KiB/text, 256 KiB total. Exact 0700 home / 0600 files are permissions, **not encryption** or same-UID containment.

The capture owner uses a short action-only redraw delay, not a deterministic paint barrier. Earlier blank editor PNGs did not establish blank live rendering. Physical input/IME, desktop clipboard, power-loss recovery and stalled kernel filesystem syscalls remain unqualified.

The PUBLIC restart fixture covers a clean two-process Unicode draft recovery, explicit recovery review, and newer text while an already-joined save outcome is undelivered. The [interruption runner](<../scripts/qualify-draft-interruption.py>) additionally exercises actual unfinished `Store::save` callbacks and nine owned native-process SIGKILL checkpoints. For a process kill with the kernel still running, recovery must return **old before successful rename, new afterward**. Feature-gated observers do not simulate a kernel-in-progress fsync or power loss; crash gates stay latched until the runner's bounded owned-process termination.

The [private-seat runner](<../scripts/qualify-private-native-seat.py>) has verified one 28-character ASCII sequence through real Wayland keyboard events into the production editor: 28 captured presses/releases, one private-seat click, exact saved text and graceful owned shutdown. Its short private runtime and pinned compositor/socket keep input off the desktop. This is synthetic-seat typing, **not** physical keyboard/IME, modifier shortcuts or desktop clipboard qualification.

## Verification ownership

Production App reducers own actions, modal/generation/changed-source fences and scroll projection. The native content module owns parser fallback and matching shaped geometry; existing PUBLIC layout fixtures own paint. Usage and private draft-store modules own their bounded input/error tests. Clipboard Tasks are not executed by model-only tests. PUBLIC renders make no Host/model requests and do not establish physical input, live provider or restart qualification. [The two-process runner](<../scripts/qualify-draft-restart.py>) exercises real App/Worker/Core/alpha lifecycle and draft Tasks in isolated homes; its App-intent and PUBLIC-record observations are not a process-wide network trace. [The file-flow runner](<../scripts/qualify-composed-files.py>) verifies real admission receipts and joined draft exit, retaining the keyless pre-step rejection and zero-model-step checks.
