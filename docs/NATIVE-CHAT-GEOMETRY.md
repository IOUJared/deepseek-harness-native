# Native content-aware chat geometry

The new presentation measures the bounded plaintext preview with the same pinned Iced 0.14 native paragraph renderer, DejaVu Sans 15px, advanced shaping, default 1.3 line height and Word wrapping used to draw it. Short user messages have narrow right-aligned bubbles; assistants remain unboxed on the left. Fixed 24px headers contain local read-only details controls instead of a separate footer. The 87px minimum raw chat slot includes all header/padding/gap/body geometry; longer previews grow to a 145px cap. Body height can contain four complete 19.5px paragraph lines (78px), not the earlier 75px partial-line cap. Stored records are never deleted or renumbered by this presentation.

The same measured height vector drives virtualized ranges, top/bottom spacers, rendered row heights and pure-prepend page displacement. Tool calls/results stay at 40px, and other raw metadata/unknown roles stay at 160px. The bounded cache retains at most4,097 sequence entries (4,096 stored rows plus a cache-only partial); role/preview changes invalidate both geometry slots, and session selection clears it. The subsequent [large-history performance refinement](<NATIVE-HISTORY-PERFORMANCE.md>) retains the two most recent effective measurement widths per entry without duplicating plaintext; a third width replaces the least-recent geometry. Chat widths above the existing640/800px caps share exact measurements, while tools/opaque records preserve actual lane width. Cache diagnostics omit preview text. Fonts are fixed after renderer initialization; a future dynamic-font feature must recreate the cache.

## Remaining limits

Plaintext previews remain capped to four explicit source lines/240 code points and four displayed paragraph lines; bounded reducer display source is available via details; the subsequent [assistant Details refinement](<NATIVE-FORMATTED-DETAILS.md>) adds optional bounded basic native formatting without changing main-chat preview geometry. This is not full Markdown or a content-height rendering of entire messages. Very long unbreakable tokens may exceed Word bounds and be clipped; More/details preserve access. Rich inline diffs, underlined relative-path navigation and real edit counts remain unimplemented. The subsequent [reader-anchor refinement](<NATIVE-READER-ANCHORS.md>) implements durable row/intra-row preservation and old-display-neighbor fallback across reflow/projection changes, with separately scoped model and native-operation evidence. Retention fails closed rather than evicting. This earlier geometry qualification does not establish physical scrolling under resize/live generation or preservation of replaced/partial content. Physical input, IME, accessibility, compositor fractional scaling, real credentials/models and full desktop parity remain unqualified.
