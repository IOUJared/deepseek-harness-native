# Composed native live decisions

## Developer fixture scope

The [example](<../app/examples/decisions_composed_smoke.rs>) compiles the actual native App/handlers/view, worker, decision reducers and renderer. A new private profile adds only a [fixture Loader module](<../app/examples/support/decision_host_fixture.mjs>) and fixture-local approval `ask` configuration. The existing native Core starts its ordinary same-version alpha desktop bundles through public profile boot; no manually assembled Cordis tree, fabricated Remote Event, guessed Agent ID or production test hook is used. This fixture is separate from the production application's read-only keyless smoke and the immutable development package.

Only a new canonical private output below native evidence and application scale 1/1.25 are accepted. Its HOME/XDG/workspace/Host profile/data are isolated. The [runner](<../scripts/qualify-composed-decisions.py>) clears the environment and retains owned pidfd process identities through cleanup; it does not modify desktop settings or installed profiles/runtime. Private protocol markers and metadata receipts use bounded fixed names, no real API key/account credential or arbitrary plugin override argument. Loopback HTTP/WS authorization still creates a local private browser-session grant; "no real credentials" does not mean no authentication material.

Every physical business/edit/model/settings/interaction message is dropped by the example wrapper. Only own window observations, real worker events, fixed script actions, deadline and close enter. Screenshots come from its own Iced renderer, not the desktop. Scripted actions and application scale 1.25 do not qualify keyboard/pointer/IME/accessibility or compositor fractional scaling.

## Real request path

The fixture creates a real top-level Agent through the injected factory, using the returned exact handle. It waits for actual root stream and successful session roster before waking that Agent once with a fixed PUBLIC message. A permanently rejecting scoped `agent/pre-step` listener holds one actual driver-owned turn while requesting:

1. Approval **Allow once** of a nonexistent PUBLIC fixture operation. No tool is registered or executed by the fixture. The Host service creates its real turn-enclosed `approval/asked`/`approval/decided` audit pair.
2. One ordinary question batch with multi-selection, fixed public custom text and an explicit skip.
3. Another ordinary question cancelled explicitly through the native question-only Cancel control; actual Host settlement must be `ASK_CANCELLED`.
4. A final ordinary question aborted by a fixture Host signal after its native delivery is observed. Actual root Cancel and `ASK_ABORTED` settlement are both required; the parent turn signal is not aborted.

The real remotes source/Gateway issues delivery/event IDs. The real native mux captures `EventDelivery`; worker mints the GUI key and validates the submitted request/answer. The example dispatches actual `App::update(Interaction(...))`, never constructs an outbound RPC. It separately observes matching complete worker submissions/ACKs, UI retirement and direct Host-service promise receipts. A successful reply ACK is not substituted for Host settlement. Each next phase waits for both, and Host abortion sends no native answer/cancel RPC. Actual root Agent ID is compared against the fixture's returned Agent, not inferred from a session row. No audit ID is reused as a Remote Event ID or worker key.

After all four requests, the pre-step listener returns `reject`. Incremental events of this one fresh exact Session must show one closed turn, one matching approval pair and zero admitted steps, request headers, tool calls/results or assistant messages. Only after the observed turn-end does the fixture await idle/quiescence and dispose its handle. Shutdown closes marker intake, aborts waits and awaits owned work/handle disposal; disconnecting a native observation alone is never treated as Host business cancellation.

## Qualification and limits

A passing runner requires actual own-PID/native-Wayland application ID, unchanged binary identity, private own-renderer PNGs, three matching native reply acknowledgements, four separately checked Host settlement receipts, exact Agent correlation, successful roster, Host-abort Cancel, closed zero-step turn and disposed root, plus graceful zero exit/no observed owned survivors before external cleanup. The [Python oracle tests](<../scripts/test_qualify_decisions.py>) reject mismatched root/counts/cancellation/receipts and invalid/nonprivate/oversized/symlink reports. Fixture-local Rust tests reject physical business forwarding, stale worker receipts and failed-roster admission. Parent paint inspection is separately recorded, not inferred from PNG presence or script success.

The full ordinary desktop composition still mounts account/Codex services and the worker subscribes cached account state. The driver assembles prompt inputs before `agent/pre-step`. Zero admitted model steps is an exact fixture-Agent event observation, **not** a process-wide LLM/tool/account/network trace or absence of those services. No model catalog, account sign-in/profile/balance or real credential request is scripted; arbitrary contributors in other profiles are outside this scope. Approval Reject/Cancel, actual tool execution, timed/continued questions, multi-client/reconnect, physical input and full feature parity remain separate qualification work. [Delivery ownership](<NATIVE-DECISION-OWNERSHIP.md>) and [timed claim ownership](<NATIVE-TIMED-QUESTIONS.md>) remain independent prerequisites.
