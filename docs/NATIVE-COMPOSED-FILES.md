# Native composed file-flow qualification

Reference for the scripted production App → Worker → Core → same-version Alpha Host file flow. The [native one-file composer](<NATIVE-FILE-PROMPT.md>) remains explicit absolute-path Review → Upload → Send, not an OS chooser. This qualification uses actual private uploads and actual Host admissions, not simulated upload/ACK metadata. No dependency, installed profile, desktop configuration or production Alpha service is changed.

## Actual consumer path

The [standalone driver](<../app/examples/file_composed_smoke.rs>) includes the production App and supplies its real worker Handle/Feed. It executes App boot, update, subscription and view in an own Iced/wgpu Wayland window. Helpers only inspect readiness, current editor consent, safe metadata/tickets and the production-generated pending request ID; they never overwrite App state, insert a receipt or fabricate an accepted ACK. Physical business/editor/model/account messages are dropped; only the fixed script drives the public App messages. Window bookkeeping and production layout-task feedback remain forwarded.

The script waits for real roster, root/registry readiness and the selected ordinary v4 snapshot. It opens path review, submits a path edit, verifies the earlier Upload stamp is refused and uses the new consent stamp to upload. Actual FileStaged delivery must match the current ticket, basename and byte count. Actual Send constructs its own `native-{pid}-{nanos}-{generation}-{serial}` request; its matching real FilePrompt ACK must clear the unchanged local draft. The script then independently waits for the corresponding Host durable inbox insertion, exact claimed file reference and blocked turn before moving to the next file.

Two malformed current-ticket worker probes per file—caller-supplied File content and unsupported Steer mode—must each yield NotSent without consuming ready authority or clearing text. Successful submission still goes through production App Send. Duplicate Send before ACK and again after the matching ACK cannot add another prompt. A stale Remove and a replay of the unchanged previously received real file ACK cannot clear a newer ready draft. The replay checks the production callback consumer; it is not an actual duplicate wire-delivery experiment or a globally exactly-once guarantee.

## Test-owned Host and storage evidence

The [fixed Loader fixture](<../app/examples/support/file_prompt_host_fixture.mjs>) mounts only in new, owner-private sibling test homes; the complete supported public base+web profile remains intact. Its optional appRequests mode permanently binds the production-generated request ID on the first valid ordered durable insertion, pins process/generation and checks serial 1/2/3 plus exact static text/file references. Claimed-message emit identity and durable inbox removal are checked separately. The default fixed-ID mode still serves the separate headless worker qualifier.

Only the exact test-owned registered root is intercepted: every pre-step is rejected, even on malformed fixture input; unrelated Agents delegate normally. Three balanced blocked turns, zero steps/request headers/tools/user or assistant messages, owned root disposal and normal observed Rust/Node teardown are required. Admission does not establish model execution, `user/message` history or history-driven receipt retirement. Scoped zero counters are not a process-wide network/credential trace.

The [independent runner](<../scripts/qualify-composed-files.py>) correlates raw private Host phase/completion receipts to App request IDs/tickets and independently reads complete known canonical objects/named aliases. For 5003-byte text+file, empty file-only and exact 4 MiB text+file fixtures it validates SHA-256, verbatim bytes, 0400 file modes, inspected 0700 directories and hardlink identity. A separate unsubmitted fixture must not have a canonical stored object. These default-provider results do not promise storage rollback/deletion or universal provider behavior.

The [strengthened default headless regression](<../app/evidence/native-file-prompt-03/native-prompt-qualification.json>) also passes. The [driver test log](<../app/evidence/file-composed-tests-03.log>) records 424 tests, including five wrapper isolation/readiness/capture-owner/close-revocation groups; [13 independent denial groups](<../app/evidence/file-composed-validator-tests-01.log>) pass. The [parent manifest](<../app/evidence/parent-native-composed-files-qualification.json>) pins artifacts, observed source ends and evidence separately from historical manifests.

All six own-window images were decoded and visually inspected: path review shows Upload/Cancel and visible storage/no-deletion consent; actual ready 5003-byte and empty-file rows show Remove and enabled Send; one Settings and visible Stop remain in the frame. Hyprland tiled the window to a 1272×1402 physical renderer buffer in both runs. Application scaling does not establish native compositor fractional scaling, tiny-frame geometry, input reachability or accessibility. The runner itself checks only bounded PNG headers/dimensions/private modes/hashes; parent paint inspection is separate.

The final text+file images also visibly paint the exact PUBLIC editor text verified by the App and Host. Earlier runs 01/02 admitted the same actual data but omitted editor glyphs in screenshots: an intermediate capture App message rebuilt Iced's editor, invalidating its old renderer Weak before the screenshot action used the previous primitive list. The fixture now chains a cancellable silent delay into the screenshot action, pausing only its own advancement Tick while retaining the App feed/window subscription and independent deadline. It does not change production editor code or promise an atomic frame fence; the observed images establish this capture case, not widget keyboard/pointer/IME input. [Feature-enabled consumer checking](<../app/evidence/file-composed-consumer-check-02.log>) passed.

The original frozen blocked-turn captures expose default raw inbox/policy cards when no user-message history exists. [Later quiet conversation/disclosed-record qualification](<NATIVE-RECORDS-PROJECTION.md>) uses the same actual admission path: recognized ordinary metadata is secondary, cancellations/future carriers stay visible and all retained rows remain disclosed. The current driver/validator additionally require a real record-disclosure roundtrip and fourth screenshot; the historical reports and hashes above remain unchanged. Pending-message/history semantics are still incomplete; no bubble is invented from an admission ACK.

## Remaining limits

OS-owned chooser/drag-drop, previews/images/downloads, actual physical input, real provider file consumption, user-message/history retirement, prompt HTTP ACK-loss races, representative integrated performance and standalone install/update parity remain pending. Reads and finite screenshot writes stay joined/owned, but admitted regular-file kernel I/O can delay shutdown. No fresh release/distribution/performance qualification follows from these debug fixtures; current installed runtime/data and desktop settings remain preserved.
