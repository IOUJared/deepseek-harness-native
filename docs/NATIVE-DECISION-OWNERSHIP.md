# Native live-decision ownership

## Scope

Approval and untimed-question replies are admitted by the native worker, not only by UI controls. An exact received delivery, worker-issued key, supported request and valid explicit answer are required. Timed and continued UI remain unsupported. This reference describes the worker/transport implementation, not a real registered-Agent/Gateway/tool/native-input qualification; the development archive and earlier source hashes are separate immutable snapshots.

A later [real composed native qualification](<NATIVE-COMPOSED-DECISIONS.md>) exercises the unchanged production owner/admission path through the complete worker and actual Gateway/registered-root/turn/services for Allow once, structured question answer, UI question cancellation and Host abortion at application scales 1/1.25. That separately scoped runtime evidence does not retroactively turn the earlier model/fake-wire record into real Host qualification; timed/continued UI and native input remain outside it.

## Exact transport delivery

[Event delivery](<../transport/src/event.rs>) is an opaque non-Clone/non-serializable `EventDelivery`. The mux actor captures the private registration at **item intake** and carries it alongside the queued JSON. `NativeStream<RemoteEventFrame>::next_event()` returns `OwnedRemoteEvent {frame, delivery}`: Waterfall has its exact capability; Ready/Emit/Cancel do not. A late dequeue therefore cannot manufacture authority by looking up an event ID that the Host has already cancelled and reused. The existing `next()` remains a DTO-only consumer and discards the local delivery handle without replying or delegating.

Root Cancel, root-stream teardown, client invalidation and successful reply acknowledgement revoke that registration. `is_live()` is a local retirement check, not exclusive authority or proof of business outcome. `cancelled().await` also wakes on this client's own ACK. Discarding a local handle never cancels the question, delegates or stops a Turn.

`reply_approval_for`, `reply_question_for` and `cancel_question_for` take the worker-held exact delivery rather than performing a fresh ID lookup. They check generation, expected kind and private Arc identity before queuing, after acquiring shared RPC capacity and immediately before transmission; revocation interrupts the pending future. A successful ACK retires only that same Arc, never a new delivery with the same ID/client/kind. Transport errors never expose raw Host messages. A transmitted request may already have won or failed even if the read is cancelled; no remote rollback, guaranteed not-sent result or business settlement is inferred.

Development API: exported `EventDelivery`/`OwnedRemoteEvent`, `next_event` and the three exact typed result methods. The legacy ID-based reply/cancel/timeout/delegation methods preserve `.await` call syntax but now return futures that synchronously capture the current exact delivery at function invocation, before their first poll. They do not discover the request's Agent/call or validate native answer semantics. New production native code uses the owned API. Exhaustive/internal Root event consumers adopt the worker-issued metadata; raw alpha DTO fields and Session formats are unchanged.

## Worker admission and UI keys

The [coordinator](<../app/src/decision_worker.rs>) privately retains at most 64 entries and 512 KiB of accounted request/identifier storage. Each observation binds actual Agent, event ID, supported request, exact carrier owner and a checked monotonic serial. The GUI receives only a cloneable `Key {epoch,event_id,serial}`, never the delivery capability. The [UI](<../app/src/ui.rs>) refuses a Waterfall without a matching worker key; [Decisions](<../app/src/interactions.rs>) adopts monotonic keys with gaps, rejects zero/replayed serials and checks attempt-counter overflow. A fixture-only local key helper has no production reply authority.

Both UI and worker reuse the request decoder. Timed, malformed, oversized and unsupported batches cannot become queued worker replies merely by constructing a `Submission`. Supported questions additionally require exact complete ID count/set, offered unique labels, valid single-/multi-select/custom combinations, bounded nonblank custom text and a complete answer no larger than 32 KiB. An empty selection with no custom is the explicit wire skip. Approval kind/outcomes are checked, and `Unavailable` cannot silently replace a user choice. User Cancel is question-only, never a Turn-stop operation.

[Worker dispatch](<../app/src/worker.rs>) checks epoch, smoke/shutdown, exact owner liveness, key, request semantics, task capacity and one active attempt. Attempts must be nonzero and strictly increase for the delivery; global UI attempts can have gaps. An already-active exact duplicate is ignored **before operation-capacity rejection**, so it cannot generate a false error receipt that resets the real pending submission. Other denied commands cannot settle a different active attempt. A transport recheck covers cancellation after worker admission.

Root Cancel removes the corresponding local entry. Matching ACK retires the delivery; failure retains only a still-current entry for a separately explicit newer attempt. Cancel/reuse and old completions cannot change a newer key. In-flight entries are **not swept merely because `is_live()` becomes false**: this client's successful ACK revokes its token before its task result reaches the worker. Shutdown revokes the generation, aborts async operations and joins the existing task owners; no admitted request rollback is promised.

## Verification and limits

[Parent verification record](<../app/evidence/decision-ownership-01/verification.json>) contains exact implementation/test identities, commands, corrected failures and scope. Seven transport ownership groups, five privacy doctests, 46 focused worker and 19 interaction tests pass; final bounded-read helpers and 12 coordinator groups were retested separately. All-target consumer compilation passes. No complete app test run, released binary rebuild or native paint/input qualification is asserted.

[Transport delivery tests](<../transport/tests/support/event_delivery.rs>) use the real authenticated native client against an isolated Node protocol fixture. Deterministic typed WS barriers exercise intake vs delayed dequeue, unpolled legacy futures, RPC-slot queueing with Cancel/same-ID reuse, an already transmitted old response, kind mismatches, exact question cancellation, failure/explicit retry and stream/generation revocation. The admitted-response test checks that new authority survives the response/cancellation race; it does not force a particular late-ACK cleanup interleaving, whose exact-Arc comparison is also source-reviewed. They are not an assembled Harness question/Agent composition.

[Worker tests](<../app/src/decision_worker_tests.rs>) cover ticket/attempt/schema/bounds/counter and cancellation/receipt behavior with private model owners. Two additional tests pass a real fake-carrier delivery through the actual native frontend reducer, coordinator and exact reply API: an explicit approval gets a matching ACK, while a timed question admits no answer/cancel/claim RPC. Those calls use production components but do **not** instantiate the complete Iced application worker loop, real Host or physical input. Other existing worker and interaction regressions remain independently relevant.

Timed integration still requires [owned question claims](<NATIVE-TIMED-QUESTIONS.md>), terminal/delivery/answer race coordination, claim retention beyond reply ACK, actual Agent/call binding, honest uncertain outcomes and isolated real-composition tests. A delivery token is **not** a timed lease; its own ACK retirement must not release that lease. Continued projection/inbox reconciliation remains separate. No automatic approval, answer, delegation, provider request, policy mutation or countdown is added.
