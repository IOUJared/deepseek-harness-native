# Native Details source copying

Reference for the explicit **Copy source** control in native Details. It copies the frozen, bounded reducer display source in either Source or Formatted mode—not rendered text, record/timestamp metadata, raw wire data or a guaranteed complete final reply. Reasoning/tool-call text can be part of that display source. Formatting, links and code remain inert; see [formatted Details](<NATIVE-FORMATTED-DETAILS.md>).

## Admission and effects

The [App](<../app/src/ui.rs>) requires effective Details visibility, the current conversation generation and the exact frozen panel opening stamp. Settings, export, management, decisions, closing and shell covers reject queued Copy actions. Back, reopening and conversation changes retire old tickets. A disconnected readable panel can still copy its original snapshot; later transcript updates do not refresh it. The final valid ticket remains usable after opening-counter exhaustion.

The [panel](<../app/src/detail_panel.rs>) permits only nonempty source at most 32 KiB in UTF-8 bytes, using the [parser's shared source bound](<../app/src/formatted_details.rs>). Empty or oversized source disables Copy rather than clearing the clipboard or silently truncating. Successful admission creates one native Iced Standard-clipboard write task; it does not read the clipboard, target Primary selection, dispatch a worker command, upload/send data or change draft/reader/send authority. Clipboard contents are available to other applications; storage and wiping are not guaranteed. Iced provides no write acknowledgement here, so the UI does not claim “Copied” success. Already-admitted platform tasks are not revoked by a later Back action.

[Copy qualification](<../app/evidence/detail-copy-source-h2s9xcjb/qualification.json>) records 22 Details admission tests, including five Copy cases, and 479 default / 486 feature / 488 layout-example / 490 scroll-example regressions. Existing covered-state matrices reject Copy as well. Tests check exact source and task admission, then drop every clipboard task without executing it. All-target feature checking and explicit four-file formatting pass; full-App formatting remains unqualified.

[Four native paint cases](<../app/evidence/formatted-details-paint-nn0d28p4/qualification.json>) exercise the actual App Source, wide/narrow Formatted and unsupported Source fallback views. Each has exactly one contained Copy source control and Back, expected format controls, zero business effects and a directly inspected own-renderer PNG. The [narrow preview](<../app/evidence/formatted-details-paint-nn0d28p4/assistant-details-narrow/own-window.png>) retains the quiet toolbar and readable native body. No Host, clipboard executor or desktop capture ran. Physical clicks, OS clipboard output/ownership, accessibility and integrated performance are not qualified.

The original Copy qualification above covers current source and the frozen scoped renderer probe. A subsequent [explicit-Node/default release qualification](<NATIVE-EXPLICIT-NODE.md>) separately rebuilds the default executable with Copy source included and confirms all four assistant Details frames are byte-identical to that inspected probe; the tool Details Copy control is separately inspected. The later [current development archive](<NATIVE-DEVELOPMENT-PACKAGE.md>) now includes this action with verified extracted startup; the older ba14 archive remains unchanged without it. These package runs do not execute clipboard tasks or qualify OS clipboard output. Installed Harness runtime/profile/GUI and desktop settings are untouched.
