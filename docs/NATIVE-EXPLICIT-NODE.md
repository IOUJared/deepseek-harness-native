# Native explicit Node interpreter

Reference for the native app's optional `--node ABS_NODE_EXECUTABLE` argument. Omission preserves Core's fixed `/usr/bin/node` default; no ambient PATH, working-directory executable or installed Harness runtime is adopted. The explicit same-version alpha Host runtime, native home, user home and workspace remain separately required. This is interpreter selection, not bundled-runtime or installer support.

## Validation and startup

The [native parser](<../app/src/config.rs>) accepts one explicit absolute path without parent traversal or ASCII control characters. It preserves spaces and Unicode, rejects duplicate/missing values without echoing caller paths, and passes the option directly to existing Core configuration. Parsing does not probe or execute the selected interpreter. `--help` starts no Host or GUI.

[Core validation](<../core/src/options.rs>) canonicalizes the selected path and requires an executable regular file before startup. The [owned spawn](<../core/src/lib.rs>) uses that validated absolute executable with its existing cleared environment and fixed `/usr/bin:/bin` PATH. Explicit selection does not redirect PATH-based tools or bundle shared libraries, assets or the Host. Executable validation is not Node authentication, version certification or immutable exec-time inode binding; no new Core version policy was added. Only the separately observed Node version in qualification is certified for that run.

## Qualification

The [private-Node qualifier](<../scripts/qualify-explicit-node.py>) copies the actual system Node into a fresh owner-private evidence directory, checks identical bytes and the strict observed v26 version, then starts the actual native binary with `--node` pointing to a path containing spaces and Unicode. An already pidfd-pinned owned descendant must match that private executable path and device/inode before and after PID/start-time checks. These are point observations, not adversarial containment or atomic execution binding. No credentials, model prompts or desktop settings are used.

The qualifier reuses existing owned-process cleanup and validates the real blank session, fold, native Wayland window/PID, complete own-renderer capture and graceful shutdown. [Pure observation tests](<../scripts/test_qualify_explicit_node.py>) check path/inode mismatch, missing/reused identity and read errors without starting a process or reading live `/proc`. [Fresh qualification](<../app/evidence/explicit-node-app-9geecs7m/qualification.json>) passes five added parser cases, five pure observation tests, 484 default / 491 feature / 493 layout / 495 scroll regressions and all-target checking. It pins the separately rebuilt default release and [29 native frames plus default-interpreter startup](<../app/evidence/control-layout-952lk4vy/qualification.json>). Actual private-copy starts at [scale 1.0](<../app/evidence/explicit-node-app-9geecs7m/private-node-scale1/result.json>) and [scale 1.25](<../app/evidence/explicit-node-app-9geecs7m/private-node-scale125/result.json>) observe Node v26.10.0, matched executable path/inode, one real blank session, zero model/catalog requests, graceful exit and no remaining observed owned identities. Both own-renderer PNGs were directly inspected; native input and representative performance remain unqualified.

## Distribution limits

The subsequent [current development archive](<NATIVE-DEVELOPMENT-PACKAGE.md>) now supports the option through both app and launcher; older ba14 archives remain unchanged. The launcher revalidates the canonical executable path, probes the selected trusted interpreter with its strict existing Node-26 policy, and forwards exactly that selection. Default `/usr/bin/node` remains unchanged; explicit failure does not fall back. [Archive qualification](<../app/evidence/package-node-copy-refresh-qpwmgtsn/qualification.json>) includes default/private-copy startup at both app scales, owned path/inode point observations and directly inspected paint. This does not add a Core version policy or authenticate the chosen executable. Shared-library/runtime/license closure, self-contained packaging, general Linux portability, physical input, actual model/account calls and full parity remain unfinished. Installed Harness runtime/profile/GUI and desktop configuration are unchanged.
