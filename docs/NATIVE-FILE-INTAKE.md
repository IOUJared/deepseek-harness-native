# Native selected-file intake foundation

This is headless worker functionality, **not a file chooser, composer attachment UI, preview or prompt-binding implementation**. It extends [raw upload](<NATIVE-FILE-UPLOAD.md>) and the [actual Host commit-uncertainty qualification](<NATIVE-UPLOAD-UNCERTAINTY.md>). No renderer, desktop configuration, installed Web GUI or Alpha business-service code is replaced.

## Local intake

[SelectedFile](<../app/src/file_intake.rs>) consumes a private, non-Clone/non-Serialize absolute Linux path intent. Its constructor validates at most 4096 path bytes, no NUL and a literal valid UTF-8 display leaf using the existing `FileUpload` name policy, without any open/stat/read. It is not an already opened inode lease: selection can change before opening.

Only an admitted owned blocking worker opens the path `RDONLY|NONBLOCK|NOFOLLOW|CLOEXEC`, checks the opened descriptor is a regular file and refuses an oversized preflight length. Reads use a fixed 4 MiB ceiling, at most 64 KiB per read and a one-byte growth probe. Stale/shrinking/growing lengths cannot grow the body beyond the limit; an empty file and arbitrary bytes remain supported. The entire read body is moved into the existing private `FileUpload`, without a GUI/body getter or serialized local path. Failures are closed static variants, not file names, raw OS errors or path echoes.

Cancellation is checked before open, between reads, after intake and before upload polling. `NONBLOCK` prevents FIFO open waits, not unhealthy regular-file kernel I/O. Final symlinks are refused; parent symlinks/path traversal are not filesystem confinement. No atomic file snapshot or hard kernel-I/O/deadline guarantee is implied.

## Native worker ownership

The [worker](<../app/src/worker.rs>) accepts `StageFile` with [attachment ticket state](<../app/src/attachments.rs>): transport epoch, selected follow generation, monotonically admitted nonzero serial and exact SessionId. A Session-address selector alone is insufficient: staging stays disabled until a correlated first snapshot with supported version 4 and no subagent origin. Header `parentSession` lineage is not structural Agent ownership; the snapshot is a point-in-time ordinary-header selection, not a live registry lease. The Host still applies its actual live/cold resolver checks.

One local operation or staged receipt is allowed. The worker stores receipt/value privately; `FileStaged` exposes only ticket, file name/byte count or closed outcome. Matching explicit discard cancels active work or removes local receipt authority; a foreign ticket cannot release the slot. Local discard is **not** Host receipt retirement or object/alias deletion. A replayed admitted serial is refused; a refused serial does not consume the frontier. Selection/follow loss invalidates the receiver and staged authority. A canceled read/upload slot remains reserved until its actual blocking closure joins; stale successful replies never become new staged authority.

File jobs, ordinary task jobs and one active export share the existing eight-operation admission budget. That is not an eight-prompt or Host work quota. A file closure independently checks its local cancellation, global shutdown and GUI delivery loss before filesystem work, between reads and before upload; async upload races those cancellation sources. Joining the local closure does not imply an aborted SDK worker or detached Host handler is already quiescent. The SDK's independent eight-upload/4 MiB limits and client-close drain still apply.

Shutdown invalidates local file authority and requests Core stop/client invalidation before carrier closure and file joins. Non-abortable admitted blocking reads are retained and joined, never detached or mislabeled canceled merely because an async wrapper was aborted; an unhealthy filesystem can therefore delay final shutdown, as with existing export saves. No automatic retry, prompt submission, rollback or storage cleanup occurs.

## Evidence and regression

[Actual headless worker report](<../app/evidence/native-file-stage-02/result.json>) passes consuming public source files of 0, 5003 and 4 MiB bytes through the production worker/Core/HTTP/default provider. Pre-selection/no-snapshot, foreign-discard blocked replacement (three times) and stale follow-generation submissions are refused. The [independent storage report](<../app/evidence/native-file-stage-02/native-stage-qualification.json>) reads all static fixture canonical/alias bytes, verifies digests, 0400 files, 0700 inspected directories and hardlink identity; the separately hashed refused fixture was not published. Both selected snapshots contain only policy metadata. Scoped remote event counts and scripted model/catalog calls are zero; this is not a process-wide provider/network/credential trace or physical GUI input.

[Focused worker regression](<../app/evidence/file-intake-worker-tests-02.log>) passes 85 groups, including 29 new intake tests, six single-ticket/private-state tests and four snapshot/closing/shared-budget guards. [Full native-app regression](<../app/evidence/file-intake-native-tests-03.log>) passes all 360 tests; [feature-enabled all-target consumer checking](<../app/evidence/file-intake-consumer-check-01.log>) and [seven Python validation/storage-denial groups](<../app/evidence/file-intake-validator-tests-01.log>) pass. Earlier [full-test failure](<../app/evidence/file-intake-native-tests-01.log>) remains preserved: a concurrent layout update left the older-page anchor test at an obsolete 960px expectation; the separate UI writer corrected it to 887px. The [first owned run](<../app/evidence/native-file-stage-01/result.json>) remains failed: its runner named a nonexistent isolated user-home directory; the corrected second run uses the prepared `user` directory without changing the compiled example. Neither failure is silently promoted.

The [example](<../app/examples/file_stage_smoke.rs>) and [owned runner](<../scripts/qualify-native-file-stage.py>) use explicit private homes and the unchanged supported public Alpha composition. Their observed pidfd-owned Rust/Node cleanup ends normally without parent intervention; this is not adversarial total descendant containment. [Parent source/artifact/evidence manifest](<../app/evidence/parent-native-file-intake-qualification.json>) freezes this bounded foundation. No native release build or new paint qualification was performed by this intake work; concurrently qualified UI builds and historical development archives do not inherit attachment UI or prompt-binding proof.

Actual delayed file-read/carrier cancellation composition, partial-write/provider/cold-resolver races and admitted-kernel-I/O delays remain unqualified beyond the focused source/unit fences and existing separate transport/Host tests. Local closure join must not stand in for server-observed disconnect or complete Host/SDK quiescence.

## Chooser and next integration

Cached `rfd` 0.17.2 Linux source was reviewed, not adopted: its async picker delegates to an unjoined spawned thread and portal failure can spawn a Zenity fallback; `FileHandle::read` additionally performs unbounded `std::fs::read` and unwraps failures. A future picker must preserve owned dialog/helper cancellation and parent-window lifetime, and must not call that unbounded reader. No new package dependencies, dialog, helper process, MIME validation, image decoding or preview are added here. Context7 quota was exhausted; this is pinned cached-source review, not a claim about latest upstream releases.

The subsequent [native file draft/prompt integration](<NATIVE-FILE-PROMPT.md>) adds explicit native absolute-path review, Upload and exact-ticket Send with private worker receipt binding. Its actual Worker/Host inbox qualification and PUBLIC renderer fixtures are separate from the frozen intake manifest above. An OS chooser, images/previews and real model consumption/history retirement are still pending; transaction or ACK proof alone is not that parity.
