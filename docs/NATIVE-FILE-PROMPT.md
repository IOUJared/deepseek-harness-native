# Native single-file draft and prompt admission

The native composer now offers **+ File path**: enter an absolute Linux file path, review it, explicitly **Upload**, then **Send**. This is a native text/path review, **not an OS file chooser**. There is one local attachment slot, with a 4 MiB file ceiling. [Bounded intake](<NATIVE-FILE-INTAKE.md>) and the existing [raw upload SDK](<NATIVE-FILE-UPLOAD.md>) remain the underlying byte path. No Electron, primary webview or new dependency was introduced.

Native Wayland drag-and-drop is also absent: pinned Iced core 0.14.0 documents `FileHovered`, `FileDropped` and `FilesHoveredLeft` as not implemented on Wayland. No unsupported event-only file-drop route or XWayland fallback is installed. OS chooser and drag-and-drop parity require a separately owned and qualified native selection integration; absolute-path review remains available.

## Local review and private authority

The [frontend draft](<../app/src/attachment_draft.rs>) contains only path-review input, scoped tickets, safe name/size metadata and closed outcomes. It never receives upload receipts or file bodies. Opening identity and advancing revision distinguish the current editor from a reopened editor: FIFO input from one paint can continue editing, but an old Upload/Cancel action cannot consent to a subsequently edited path. Paths are validated without filesystem I/O; admitted reads remain worker-only.

The [actual App](<../app/src/ui.rs>) hides path review until requested and displays a compact file row. Upload is explicit consent to storage **before Send**. The visible review explains that removing/canceling may leave stored bytes. Removal first delivers the exact-ticket discard to the worker; a full local queue does not silently drop the frontend's remaining authority. Cancellation/removal stay available during a temporary model-selection restriction, but not behind an inactive modal or during an already dispatched file prompt. Selection/reload/follow loss invalidate local visibility; an admitted read stays globally reserved until its exact completion or disconnection.

File-only Send is supported. Text with a file uses the same editor, model controls and Send as ordinary text. Editing/rejected/unknown/pending file state blocks Send instead of silently omitting the intended file. A queued stale Remove cannot discard a newer file. Matching upload completion may settle while Settings is open without performing a new operation behind the modal.

## One explicit prompt attempt

The [worker coordinator](<../app/src/attachments.rs>) alone consumes the private staged receipt. It validates epoch, selection generation, exact ticket/Session, matching supported ordinary snapshot header, enabled admission, Queue mode and text-only caller content of at most 32 KiB/eight parts. It inserts the receipt into the request privately. Generic Prompt commands cannot inject a file receipt. Ordinary-header correlation is a point read, **not** a live or structural Agent lease; parent Session lineage does not establish runtime ownership.

Once dispatched, the local receipt is never restored, even on an error, drop, cancellation, negative ACK or timeout. Its slot remains reserved across selection/discard until the exact ticket/request completion. Global closing and delivery loss win before RPC polling; cancellation after dispatch drops the owned request future and reports **Unknown**, not rollback. These scheduling gates have pure synthetic-future tests, not a newly qualified actual HTTP ACK-loss race.

Frontend prompt outcomes are also exact-ticket/request correlated. Local queue/admission refusal can leave the current file ready for a new explicit attempt; nothing retries automatically. A positive ACK clears the unchanged submitted draft. An uncertain Send retains text/safe file metadata and blocks another Send until explicit removal. Text-only ACKs and foreign file ACKs cannot settle a file attempt. Request IDs include a checked local monotonic serial; exhausted authority fails closed.

Durable file-only user records display bounded file name/byte metadata with **preview unavailable**, not receipts, digests or arbitrary raw file objects. Native chooser, drag/drop, clipboard-file intake, previews/images, file download/open and richer attachment/history UX remain pending.

## What Alpha acceptance means

The exact Alpha [prompt implementation](<../../deepseek-harness-linux/packages/api/session-controller/src/commands.ts#L311-L376>) resolves the receipt into a durable file reference, binds it, synchronously queues/steers the Agent, commits binding and returns `accepted:true`. This means **Host inbox admission**, not model completion or `user/message` history. Guard rollback restores receipt bindings, not queued inbox/storage effects.

Alpha [receipt binding](<../../deepseek-harness-linux/packages/client/file-upload/src/index.ts#L150-L167>) can rebind an existing receipt until retirement; it is not intrinsically one-use. Native single-attempt policy is deliberately more conservative. Duplicate request detection checks pending inbox/user history, not a permanent all-time request ledger: a claimed/rejected request can disappear from both. Retrying the same request ID therefore is **not** generally safe. History-driven receipt retirement follows matching actual user-message events; session disposal retires maps, neither deletes persisted bytes. Local Remove/selection loss is not Host receipt retirement or storage deletion. Accumulated Host receipts/storage remain outside the one-slot local memory guarantee.
