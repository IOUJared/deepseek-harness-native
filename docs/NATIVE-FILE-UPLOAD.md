# Native bounded file upload

Reference for the explicit Rust upload adapter against isolated `0.2.1-alpha.1`. This qualifies backend intake, not attachment UI or full desktop parity.

## API and ownership

[`FileUpload`](<../transport/src/upload.rs>) consumes a `Vec<u8>` and optional display leaf. It accepts empty/arbitrary bytes up to 4 MiB; names are 1–1024 UTF-8 bytes and reject controls, slash/backslash, dot and dot-dot. No local path, automatic file read, image decoder, Clone, serialization or bytes/name getter is provided. Debug reports size only. The allocation moves into HTTP; caller, allocator, carrier, kernel and Host copies are not wiped.

`NativeClient::upload_file(&SessionId, FileUpload)` posts only `/api/session/uploadFileBinary?sessionId=…&name=…`, with percent-encoded query fields, `application/octet-stream`, exact Content-Length and existing private Cookie/Origin. No multipart, base64, arbitrary endpoint, redirect or AgentId query is used. The JSON RPC uplink ceiling does not apply to this separately bounded raw body.

Eight generation-owned upload jobs cover active and queued workers; excess admission returns `QueueFull` before transmission. They share the existing RPC semaphore. The owned input buffers therefore total at most 32 MiB across these workers, excluding caller-created/unpolled inputs and HTTP/kernel copies; this is not a process-memory or Host-storage quota. Each tracked worker owns its queued acquire/permit, deadline and body; dropping the caller aborts it, and owner invalidation/close cancels and drains it even when the caller future remains parked. Scheduling, queueing, send and complete receipt decoding share one absolute deadline, with cancellation/timer priority and pre-send/postdecode expiry checks. An unobserved completed result is rejected after generation invalidation. Other RPC/export caller-owned futures retain their existing shutdown behavior: callers must keep polling or drop them before waiting for close; this is not a broad parked-future shutdown fix.

Complete receipts are capped at 16 KiB and 128 JSON values/containers, or smaller configured transport bounds. Exact success/failure fields, typed IDs, safe display leaf and matching byte count are required. Malformed/incomplete/oversized responses fail rather than publishing partial references. Errors contain no remote body, message, details or URL. Successful [`FileUploadValue`](<../transport/src/dto.rs#L641-L653>) intentionally contains serializable/debuggable receipt/name/digest/size metadata; do not log it indiscriminately or publish receipt authority to a model. The caller must retain the requested Session, selected-view ticket and Host epoch because the response echoes neither Session nor Agent identity.

## Exact alpha behavior

The [raw route](<../../deepseek-harness-linux/packages/client/file-upload/src/http-route.ts>) accepts SessionId. [FileUploads](<../../deepseek-harness-linux/packages/client/file-upload/src/index.ts>) first checks the live registry, otherwise invokes the ordinary-Session resolver, which can resume a persisted cold Agent. Upload cancellation is not forwarded into that resolver and can still activate a Session. Native registry discovery is a read, not an admission lease; do not fabricate AgentId or promise upload cannot resume.

FileUploads rejects live `origin: subagent` before storage. Cold resolution separately rejects subagent/owned-child targets; the live lookup bypasses the resolver's broader ownership check. Ordinary files have no MIME/image/model validation and no stock streaming admission byte cap. Connection's buffered-body ceiling does not limit this raw route; 4 MiB is native policy, not a Host-wide limit.

A receipt is staged in a WeakMap keyed by the exact Host Session object, with a post-storage exact-Agent registration check. Staging is not prompt admission, a durable logged attachment reference or model generation. Unsubmitted receipts remain Session-owned; concurrent-worker limits do not cap accumulated receipts or durable objects. Subsequent [native draft/prompt integration](<NATIVE-FILE-PROMPT.md>) now adds one private local slot and conservative single-attempt prompt binding, not automatic Host retirement/deletion.

The default [local provider](<../../deepseek-harness-linux/packages/attachment/attachment-local/src/file-store.ts>) sanitizes/truncates names, stores verbatim content-addressed bytes and publishes canonical objects plus named hardlink aliases. Storage can remain after abort, Agent disposal/replacement or lost acknowledgment. A failed/expired/closed upload does not establish rollback or absence of commit; no automatic retry, prompt submission, cleanup or deletion is provided. [Actual Host uncertainty barriers](<NATIVE-UPLOAD-UNCERTAINTY.md>) now qualify default-provider bytes/receipts remaining after acknowledgment loss, and storage remaining despite late receiving-Agent refusal; these are not rollback guarantees.

## Evidence and limits

The [owned SDK report](<../app/evidence/file-upload-sdk-02/result.json>) passes two sequential actual public-profile Host epochs, live upload, unknown-target refusal, cold absence→upload→registered Agent, five fresh receipts and two graceful zero exits. The [independent storage report](<../app/evidence/file-upload-sdk-02/upload-qualification.json>) reads complete canonical/alias bytes and confirms digests, empty/4 MiB bodies, name sanitation, hardlink identity, 0400 files and 0700 inspected directories. Default local-provider layout/modes are not universal provider guarantees. Both post-upload snapshots contain only policy metadata, with alpha's ordinary `session/end-seed` resume marker in the second; this is not a process-wide model/network/credential trace.

The [fresh SDK report](<../app/evidence/file-upload-sdk-03/result.json>) and [storage report](<../app/evidence/file-upload-sdk-03/upload-qualification.json>) pass after extracting the shared oracle and adding anchored ancestor-symlink rejection. [Direct receipt transaction/refusal and handler cleanup qualification](<NATIVE-UPLOAD-UNCERTAINTY.md>) is separate from Rust SDK or native prompt admission.

[Wire fixtures](<../transport/tests/support/upload_wire.rs>) qualify admission, exact raw bytes/headers/query, complete bounds, redacted failures, explicit carrier closure, queued/admitted/parked cancellation, delayed scheduling and stale completed-result fencing. [Qualification denial tests](<../scripts/test_qualify_file_upload.py>) reject misleading metadata, nonprivate modes, mismatched bytes and symlinks. See the [parent qualification manifest](<../app/evidence/parent-file-upload-qualification.json>) for exact source/binary/report hashes and completed regression checks.

[Bounded local-file intake and private worker staging](<NATIVE-FILE-INTAKE.md>) now provide consuming path intents, regular-file checks, one owned local slot and ordinary-header/ticket/selection cancellation fences. The [subsequent native draft/prompt integration](<NATIVE-FILE-PROMPT.md>) adds native path review and actual Worker/Host inbox admission with private receipt binding. Native OS chooser/drag-and-drop, image intake/previews, generic download/output files, real model file consumption/history retirement, physical input and representative integrated performance remain pending. The [native control-layout pass](<NATIVE-CONTROL-LAYOUT.md>) is separately qualified. Historical packages do not inherit this upload qualification; including transport source or linking upload code does not establish native attachment UI or prompt binding.
