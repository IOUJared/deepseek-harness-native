# Native account observation

Reference for the private native supervisor and standalone Iced worker. The native primary UI remains browser-free; its loopback transport still uses the full isolated alpha desktop profile.

## Deferred work

The worker no longer sends `AccountSubscribe` at startup. Native readiness, sessions and workspaces do not depend on account observation. Sidebar account metadata starts **not loaded**, not signed out; lifecycle disconnects clear stale labels, late metadata is ignored, and optional subscription warnings do not disconnect the app or automatically resubscribe.

The supervisor retains a lightweight Cordis `deepseekAccount` binding, but does not call `watch()` or `getPlatformSession()` until the public Core caller explicitly requests `AccountSubscribe`. There is one private watch owner. Repeated subscriptions share it; unsubscribe aborts notification intake, clears that owner's mirrored session and joins its iterator/session read **and all admitted initial status reads**. A blocked, non-abortable observer read stays owned and prevents another watcher from starting. Cancellation cannot register or publish its late token/headers. An old provider disposer cannot clear a newer owner.

Provider loss/replacement or watch failure revokes observation and requires a **new explicit subscription**. The account observer does not retry, sign in, sign out, request a profile/balance, load models, or mutate API keys. Subscription requests remain single-flight; unsubscribe has its own priority control lane, so it can revoke a still-pending initial subscription. Replacement remains denied until that owner's watch and status reads retire. Neither control shares the existing mutation lane. The native app currently has no Platform observer action; the public Core subscription remains available for an eventual separately qualified compatibility consumer.

Each observer subscription reserves its raw `getState()` promise before execution. Retirement requires both watch completion and an empty read registry; aborted late reads cannot return successful subscription metadata. This joins provider operations without joining subscribe wrappers back into themselves. Separate one-shot onboarding/account commands still belong to supervisor pending-command shutdown, not the persistent observer. Ending observation is never cancellation, rollback or confirmation of an admitted credential write; receipt, timeout and indeterminate-save handling remain unchanged.

## Intentionally retained work

Opening ready Settings → API login still requests one-shot local metadata (`credentials.describe()` and `account.getState()`); explicit Refresh and the existing save preflight do likewise. These read configured/writable/presence metadata, do not start the persistent observer and do not export a Platform token. They do not validate the credential against a server. Codex retains its separate explicitly initiated status/authentication/model-route flow.

This is **not** a lean account-free Host. The unchanged same-version base+web composition still mounts account/controller/authorization/credential/settings/LLM services. Account initialization can read its local stored grant; credential storage loads and maintains its own watcher. The required connection also loads/creates browser-session signing material and authenticates the loopback BFF even with `--no-open`. Removing those services would require a different qualified profile/transport; it is not part of this change.

## SDK compatibility

Native version 0.1.0 previously mirrored Platform sessions eagerly and treated unsubscribe as notification suppression. It now leaves that private session absent until explicit subscription, clears it when observation ends, and admits priority unsubscribe even during initial status reading, and acknowledges it after watch/session and admitted status-read retirement. Provider replacement no longer silently restarts the observer. A caller must handle unavailable/timeout outcomes and explicitly resubscribe; an abort signal alone cannot make an unresponsive provider method settle. No public command schema, session persistence format or upstream package version changes.

## Evidence and limits

[Priority-cancellation parent evidence](<../app/evidence/parent-account-cancellation-qualification.json>) pins the current backend and production executable. [A fresh actual alpha profile](<../app/evidence/account-cancel-host-01/result.json>) retains zero native watch/session calls at Ready and during two one-shot metadata reads, then two explicit watches, maximum one live, two ended, and clean one-process exit without external signals. [Rebuilt production lifecycle](<../app/evidence/account-cancel-production-01/result.json>) passes own Wayland at scale 1.25, actual blank-session fold and graceful two-process zero exit; the 8-second smoke is not a new performance comparison. Paused native UI/layout sources remain unchanged and unqualified work stays excluded from default builds. That cancellation qualification retained the earlier 280-test app baseline and reran Core/all-target checking, not the full UI suite. The later [API receipt policy](<NATIVE-SAVE-UNCERTAINTY.md>) reruns all 285 app tests without changing the account observer or paused primary layout.

[Real alpha public-profile evidence](<../app/evidence/lazy-account-host-01/result.json>) uses the actual profile helper, full Loader/Cordis composition, shipped account provider and production supervisor. Counters attach **after public profile boot, before native binding** by delegating methods on the same loaded service; no account provider is substituted. Native Ready shows zero observed account/state/session calls in that measured interval. Two one-shot metadata operations produce two state reads and zero watches/session reads. Explicit subscribe/repeated subscribe holds one watch; unsubscribe retires it; explicit resubscribe followed by real profile shutdown yields two started/two ended watches, maximum one live, zero nonnull Platform frames in the empty profile, clean process exit 0, one observed owned Node process, and no external cleanup signals. This is not Rust stdin/frame/GUI tracing, whole-runtime credential reads or a process-wide network trace. Real provider hot replacement remains unqualified.

[The native fake-owner tests](<../core/runtime/account-observer.test.mjs>), [retirement/redaction tests](<../core/runtime/account-observer-extra.test.mjs>) and [concurrent status-read tests](<../core/runtime/account-read-retirement.test.mjs>) pass eighteen cases. Barriers cover priority cancellation while initial reading is held, zero provider calls on pre-intake cancellation, multiple raw reads and partial/failed settlement, failure-triggered stop without explicit unsubscribe, natural watch termination with pending status, provider replacement during held status reading, late-token suppression, redaction-before-emission, and pending-command shutdown. These are production-helper/supervisor tests with fake service promises, not actual blocked-provider or HMR qualification. Unsubscribe proves owned read/iterator drainage and publication fencing; it does not certify that an abort-time provider cleanup which throws succeeded. The private producer's nonthrowing diagnostic sender is retained; arbitrary throwing callbacks are outside this evidence. Four [Python oracle tests](<../scripts/test_qualify_lazy_account.py>) reject eager reads, duplicate/unretired owners, malformed types and overclaims. The complete app test run passes 280 tests, including three new account-label/dependency tests; those are reducer coverage, not production-worker call tracing. Core passes 50 tests and six privacy doctests. All-target checks and offline locked production/settings-example release builds pass after restoring the concurrent public-layout example's required-feature registration; that layout fixture is not qualified here.
