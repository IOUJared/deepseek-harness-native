# Native local accounts and Maintenance composition

## Scope

The [shared native composition example](<../app/examples/usage_composed_smoke.rs>) adds a closed `--scope accounts` scenario beside usage/runtime. It runs the **actual non-smoke App**, Settings/Codex owner, worker, typed Core private pipe and unchanged full base+web **0.2.1-alpha.1** profile. Real worker receipts are applied to App before the private oracle; no fabricated status/ACK or replacement composition.

Only a **new owned 0700 home/0600 vault document** is seeded, using the existing [PUBLIC stored-record precedent](<../scripts/qualify-managed-codex.mjs#L18-L25>). Two fixed synthetic OAuth-shaped records are test data, not real credentials/sign-in. This is not a grant importer or authentication bypass. No route patch, OAuth/Add/Connect, browser, token refresh, model activation, catalog or provider execution is requested. Source review locates authentication/refresh in the later model/auth path, not roster restoration, local selection or deletion.

| Process | Native actions and expected durable state |
| --- | --- |
| Initial | Refresh roster at 0; review/confirm first selection → 1, explicit Refresh; repeated selected-ID review/confirmation admits no operation, second explicit Refresh still 1/A; valid second selection → 2, explicit Refresh |
| Restart | Read second selection at 2; review/confirm its **local** sign-out → 3, explicit Refresh shows first account still present but **no replacement selected**; review/confirm all → 4, explicit Refresh empty |
| Second restart | Read empty epoch 4 without seed/mutation; direct empty sign-out-all review/confirm must not admit a worker operation |

After each settled Account frame, native tab navigation opens **Maintenance → Refresh connection status**. Actual `StatusSnapshot` must preserve that phase's roster/selection/epoch, and current-panel Account mutations must be rejected there. Account/status refresh performs **two local Core reads**; the fixture's admission count is native UI effects, not private-command or network telemetry.

The native checks also reject confirmation without review, absent roster IDs and invalid Add labels without an admitted operation. Account views expose public aliases/opaque ids only; email/plan/quota remain unknown. A stored selected record is not issuer identity, fresh validity, entitlement or a configured model route. Local logout neither selects a replacement nor revokes issuer credentials.

## Guard and limits

The [empty-list compatibility note](<NATIVE-MANAGED-CODEX-UPGRADE.md>) records the production owner/view fix. SDK empty sign-out-all would still retire/commit an epoch, so native rejection is checked **before dispatch**, not by executing that mutation and calling it a no-op.

The [parent qualifier](<../scripts/qualify-composed-usage.py>) verifies owned document permissions, exact manifest/record contents, unchanged PUBLIC payloads after selection, record removal after logout, content equality across the empty restart and released kernel vault flock after each stop. It preserves the original bounded pidfd supervision, outside-phase private logs and interrupt cleanup. Only owned synthetic documents are read; installed/real vaults remain untouched.

Private unsent-catalog reservation/pre-Ready Codex selection suppress unrelated startup reads; normal app startup is unchanged. Scripted actions/native renderer captures are not physical keyboard/pointer/IME/accessibility or compositor-scaling evidence. Zero-request flags describe reviewed commands/source, **not packet/firewall instrumentation**. Real sign-in/Add, cancellation during OAuth/SDK streams, provider execution, issuer revocation, quota/alerts/reset retry, arbitrary concurrent writers and crash/power-loss remain separate qualification.

Build/use the example and new evidence directory as in the [usage composition guide](<NATIVE-CODEX-USAGE-COMPOSITION.md>), adding `--scope accounts`. The native binary restricts output to its own compiled manifest's evidence directory; never point it at an installed home. No SDK/API/schema/dependency/profile-code or persistence-format changes are required.
