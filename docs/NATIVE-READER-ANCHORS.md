# Native reader anchors

This refinement builds on [measured native chat previews](<NATIVE-CHAT-GEOMETRY.md>), without changing retained events, business commands or primary renderer. The [anchor module](<../app/src/scroll_anchor.rs>) and [native operation](<../app/src/scroll_operation.rs>) are bounded, plaintext-free geometry state; the [model-only tests](<../app/src/scroll_ui_tests.rs>) run without a worker or effect executor.

## Identity and legal extent

A reader captures the durable raw-row sequence and pixel displacement within the first intersecting row, using the same native measured heights as virtualization. After width/sidebar reflow or selected-session follow/page projection changes, it finds that key in the new **display order**, not numerical sequence order. Surface replacement can reorder keys. If the row disappears, the first surviving old-display successor (otherwise nearest predecessor) preserves its old viewport-relative top where legal; no survivor resets to zero. This is best-effort fallback, not preservation of removed content. Shrinking rows keep displacement strictly inside the new row; native viewport limits can force a different top alignment.

The reducer fails closed at 4096 retained records or 16MiB serialized retention; it does **not** evict history. Pagination uses the opening cut, and an error can still change the actual projection. Restoration observes the post-operation rows even on errors. A rebaseline can change content associated with the same sequence; a sequence match is not proof of identical text.

The appended live preview contributes its measured height to the complete rendered extent but is never treated as durable identity. Its application-local `u64::MAX` label does not expose an attempt ID and may recur. No text matching or automatic partial-to-commit identity mapping is performed. Capture intentionally omits partial shaping; cache-only live geometry survives durable measurements.

## Timing and stale actions

Pinned Iced 0.14 sources rebuild view/layout after draining the current model-message batch, then execute collected widget operations. The direct custom operation clamps against the **actual rebuilt viewport/content bounds**, preserves the horizontal offset and emits one metadata-only result only if its widget exists. No sleeps, delayed restore message or notification-dependent latch is used. Fitting content may be expanded to the viewport minimum by Iced, so operated content bounds are not always intrinsic row-height sums.

A checked geometry revision and selected-session generation tag scroll notifications; old-view feedback is ignored. Operation widget IDs additionally include a checked feedback serial. Different current-view feedback invalidates an older operation/callback without rejecting later feedback from the same view batch. Own-target comparison uses the notification's actual content/viewport extent, preserving reader intent even if a clamped notification arrives before the operation result. Hidden/remounted panes, including worker-driven decision cancellation, receive fresh operation IDs and restoration requests. Checked-counter exhaustion disables programmatic restoration rather than reusing authority.

Notifications do not identify user versus programmatic provenance. Matching the current clamped target is a local hint, not physical-input proof. Following remains explicit state; a reader is not silently made a follower just because restoration lands near the end. A current differing scroll can update follow state; the explicit Latest action continues to follow the real bottom.

## Evidence and remaining limits

The first [standalone native operation report](<../app/evidence/scroll-anchors-wnhh7qb3/native-operation.json>) preserved a **fixture expectation failure**: all three callbacks/offsets and stale-ID guards were correct, but the fitting phase expected intrinsic 144px instead of Iced's operated 260px content. It is not successful qualification. The [corrected native Wayland report](<../app/evidence/scroll-anchors-wnhh7qb3/native-operation-corrected.json>) passes all three actual-layout phases: `320px`, clamped `396px`, and fitting-content `0px`; callback counts are `[1,1,1]` and stale callbacks zero. Its [own-renderer frame](<../app/evidence/scroll-anchors-wnhh7qb3/native-operation-corrected.png>) was directly inspected. This is a standalone native operation qualification, not production-App coupling or physical input.

At the standalone-operation capture, sixteen independent anchor/operation tests and eight production-App model-only scroll tests passed; that source checkpoint passed416 default app tests. Regression coverage includes reverse notification/callback order, late callback after multiple same-view feedback entries, counter exhaustion and worker-driven decision cancellation/remount. [Frozen production capture qualification](<../app/evidence/control-layout-sh5wjnfj/qualification.json>) retains the exact executables used for twenty PUBLIC frames and real isolated keyless startup/teardown. Every image matches the fully inspected preceding snapshot byte-for-byte. The [retained executable](<../app/evidence/control-layout-sh5wjnfj/compiled-snapshot/dsh-native-app>) SHA-256 is `cc26693020736e103b55860bed54ea4ad908cf08d8134fce0e62f62e52d23e37`, 15,612,832 bytes. That checkpoint's final source tests passed416 default /418 feature app /420 fixture tests; these counts include concurrent work and are not a reproducible full-source compiler closure. The capture runner now freezes executables before startup and records source stability separately, so later shared-writer rebuilds cannot silently replace the observed artifact. These actual-App captures still do not execute the reader's widget restoration pipeline or real file upload/prompt effects. Test growth includes concurrent attachment foundation work and must not be attributed entirely to anchors. Shared attachment regression fixtures additionally needed the real Settings epoch adoption; queued file actions were included in the existing modal-background fence, without relaxing admission or receipt rules.

A subsequent [production-App native integration qualification](<NATIVE-APP-SCROLL-INTEGRATION.md>) executes the actual view/update/receive/restore pipeline against rebuilt native widgets: controlled-frame rewrap, PUBLIC history prepend, decision hiding and worker-shaped cancellation/remount preserve key112/intra12, independently measured from native raw-slot bounds. It also documents a narrow viewport-only redraw intent fix and the limits of its heuristic. This is zero-Host scripted coupling, not real worker/transport or physical input.

Physical scrolling/keyboard/IME, live-Host restoration coupling, continuous live-generation input, arbitrary composer/footer viewport changes, accessibility, full-message Markdown/inline diff, exact partial attempt identity, integrated long-history performance, real OAuth/model generation and full desktop parity remain unqualified. Every selected/page frame currently measures the bounded full durable projection even if a frame is a no-op; continuous reflow costs require an integrated workload. The frozen earlier development archive does not contain this refinement. Installed runtime/user data and desktop settings were not modified.
