# Native conversation and diagnostic records

The primary native conversation no longer renders routine inbox/policy JSON cards as chat. All retained rows remain available through **Show N session records / Session records**, with the existing read-only Details action. This changes presentation only; it does not create pending user bubbles, optimistic history, model results, acknowledgements or file authority.

## One displayed-row projection

The [retained transcript](<../app/src/reducer.rs>) exposes one displayed-row iterator, used by actual App view construction, virtual row geometry, durable reader anchors and active-transcript detection. Existing exact `permission/preset`, `sandbox/mode` and `approval/policy` roles are secondary. The [inbox classifier](<../app/src/transcript_presentation.rs>) also makes only recognized ordinary `agent/inbox/spliced` insertions/claimed removals secondary.

A secondary inbox record has only target/start/inserted and optional positive removedCount, safe JavaScript integer coordinates, a known target and a real mutation. Known inserted user messages have id/content/role/source, user source with optional RPC ID/timezone and recognized text or file-reference blocks. These are conservative presentation classifications, not a new Alpha validation/provider policy. Empty file metadata and exact 4 MiB file metadata remain supported. Other producer kinds, source/message/content extensions, unknown outcomes, malformed fields and cancellation carriers remain primary; their underlying bounded data is not parsed from redacted/truncated display JSON.

An exact stored canceled inbox outcome stays visible with a red **Canceled queued input** heading and read-only details. Unknown required events still set the existing reducer error, disable Send and preserve the read-only warning. Tool results/errors, system/developer messages, assistant attempts/live text and unknown roles remain visible. Cancellation and unusual records must not be described as completed work, ordinary success or durable user-message history.

All four consumers use the same displayed durable key/order/height list. Partial assistant text remains a separate cache-only live row/trailing height, never a durable anchor. Retained raw row count remains the record-disclosure count. Opening/closing records captures the old displayed reader anchor, changes the projection and invalidates the scroll revision/widget ID before scheduling position restoration; late feedback from the prior mode cannot rewrite the new offset. Existing reader/follow-bottom intent survives. A removed anchor uses the existing neighbor rule; actual native viewport clamping can prevent exact visual alignment.

## Limits

These are native Linux debug source qualifications, not a new release/install package or measured integrated-performance result. Application scale 1/1.25 is not independently verified native compositor fractional scaling. Physical keyboard/pointer/IME, accessibility, OS chooser/drag-drop, rich files/previews, real OAuth/provider generation, continued claims/guests, user-message/history receipt retirement and distribution/update parity remain pending. Hiding only recognized routine metadata does not optimize every producer or replace proper pending-message semantics. Installed Harness runtime/profiles/data and desktop configuration remain preserved.
