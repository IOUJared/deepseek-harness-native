# Native session ZIP export

## Scope

Native session management now includes **Export session ZIP…**, an in-window dimmed/inert modal with explicit absolute destination, Review and Confirm. Its [export controller](<../app/src/exporter.rs>) fences current epoch, selected ordinary session, generation, panel lifetime, editor and attempt; one consuming submission moves the destination to the worker. Closing the panel clears unsubmitted path/review but does not cancel an admitted export, restore its draft or imply rollback. Results are fixed metadata, not archive bytes or paths. The [worker](<../app/src/worker.rs>) independently admits one export within its eight-operation budget, checks selected ordinary target/generation and excludes credential/plugin/Codex/registry writes; its current download ceiling is **4 MiB**, not the transport library's maximum 32 MiB. Downloads are cancelled/awaited at shutdown; filesystem saves run in a separately owned blocking set and are never aborted or detached. Shutdown revokes the backend first, then joins admitted filesystem work before publishing Stopped. Guards observe closing at admission, not a universal physical-syscall cutoff; an already-admitted save can finish after Close. The typed [download implementation](<../transport/src/export.rs>) uses the private authenticated client and an independently owned [destination writer](<../app/src/export_file.rs>) requires an explicit new absolute `.zip` filename. No browser download, automatic folder selection, extraction, overwrite, descendant inclusion, model prompt, session deletion or automatic retry is added. Transport compilation/formatting and **61 tests** pass (`bash-349`: 11 unit, 17 export HTTP, 30 existing transport and three compile-fail doctests). The consuming destination implementation passes **seven native filesystem tests** and the current application passes an offline locked all-target check (`bash-351`), using cached Rustix 1.1.5 safe openat APIs; existing dependency versions are unchanged. The [headless public composition example](<../app/examples/export_file_tests.rs>) now passes **10 tests** (`bash-352`: seven filesystem tests plus three actual authenticated local-fixture download→file tests), with a clean current all-target check and no warnings in that gate. Composition verifies bounded public ZIP bytes, private mode 0600, exact saved count, no overwrite and the fact that an already-returned owned archive survives input-client closure while stale requests fail. This is a synthetic local HTTP/ZIP fixture, **not** real Host/GUI/valid JSONL/CRC/DEFLATE qualification.

## Actual alpha route and contents

The isolated alpha exporter registers [GET/HEAD `/api/session.export`](<../../deepseek-harness-linux/packages/session-query/session-log-export/src/index.ts#L87-L168>), not a JSON RPC. Native GET serializes the opaque session ID once in query parameters and explicitly sends `includeDescendants=false`. The mounted HTTP path performs [operator admission before the Fetch bridge](<../../deepseek-harness-linux/packages/client/connection/src/index.ts#L144-L155>); direct in-process Fetch tests bypass that admission. Native sends its private Cookie/Origin, never a launch token or arbitrary URL, never follows redirects, and never adopts Content-Disposition as a destination filename.

False means the complete root canonical `session.v4.jsonl` **and referenced root images/files**, not log-only or redacted content. [Serialization](<../../deepseek-harness-linux/packages/session-query/session-log-export/src/archive.ts#L110-L168>) preserves committed records, workspace paths, header relationships and opaque events; an export can contain personal information, credentials or other sensitive contents. Descendant inclusion is intentionally absent: the Host lineage traversal can include ordinary fork descendants, not only subagents. No universal secret-free archive claim is made.

GET is not a pure storage read: the Host [flushes a live root before reading](<../../deepseek-harness-linux/packages/session-query/session-log-export/src/archive.ts#L80-L92>), which can materialize or update durable logs. Cancellation cannot undo a completed flush. HEAD also flushes/reads before creating and cancelling the ZIP; native must not use HEAD as a supposedly side-effect-free preflight. The stock exporter does not resolve/resume an Agent or prompt a model, but arbitrary profile persistence/attachment providers and session-flush listeners are trusted. Native default telemetry/browser disabling is not packet tracing or a universal custom-profile external-I/O guarantee.

All sessionQuery/sessionPersistence/attachments services are required, even for a root without attachments. Existing same-version private base+web-app composition supplies them; no installed-runtime package activation or profile modification is needed. Missing services/read failures return fixed 500; absent stored session normally returns 404. Missing/corrupt attachment data can fail after HTTP 200, which must never become a successful local file.

## Download and ZIP admission

The native consumer caps received bytes at the smaller of its configured result budget and 32 MiB, checks advertised length and every streamed chunk, and uses a deadline covering queue admission and the complete transfer. Revocation rejects queued/in-flight work and stale clones. The Host reads/serializes the entire root before responding; native receive/time limits do **not** globally bound Host root memory, compression CPU or all custom providers.

The [resolved fflate writer](<../../deepseek-harness-linux/node_modules/.pnpm/fflate@0.8.3/node_modules/fflate/esm/index.mjs#L2081-L2195>) uses classic ZIP, DEFLATE method 8, streaming bit 3 and signed descriptors. It has no ZIP64 writer path. Local/central DOS timestamps may differ and must not be equated. Native admission is a conservative known-writer profile: complete classic central-directory/EOCD structure and contiguous local payload/descriptor records, not a general-purpose ZIP extractor. Advertised uncompressed sizes and filenames are constrained; unknown/unsupported archives are refused rather than guessed.

No native decompression is introduced. Structural field consistency cannot establish actual DEFLATE validity, payload CRC, actual uncompressed expansion, session identity, attachment digest or sensitivity. A successful download is a bounded structurally admitted export, **not** full payload validation. Never extract it automatically or describe this guard as proof that arbitrary third-party extraction is safe. The archive holder is non-Clone/non-serializable with metadata-only Debug and no raw-byte or remote-filename accessor. Its consuming writer wipes its owned download buffer on release; reqwest/allocator/kernel/host/writer/swap copies are not guaranteed erased.

## Native file creation

The destination writer rejects relative, overlong, control-containing, dot/dotdot, repeated-separator and non-`.zip` inputs without trimming or appending anything. Every existing parent component is opened with DIRECTORY/NOFOLLOW and held through directory descriptors. No parent directory is created automatically. Final CREATE|EXCL|NOFOLLOW creates a new private file, never follows a final symlink and never overwrites an existing destination. Exact mode 0600 is applied through the newly created descriptor before content is written.

The held parent is the directory inode admitted at preparation: an external rename does not redirect writes into its replacement, but the pathname need not remain stable. This is not arbitrary filesystem confinement. Success requires exact byte accounting and file plus directory synchronization. Once a file is created, write/accounting/sync failure is indeterminate: an empty, partial or complete private file may remain. No automatic deletion, rollback, reuse of the confirmation or retry is promised. Synchronous filesystem operations may block on arbitrary filesystem behavior; no hard total wall-clock or secure-erasure guarantee is claimed.
