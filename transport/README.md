# Native authenticated transport

MIT Rust 2024 client for the **0.2.1-alpha.1 isolated fork**. HTTP and WebSocket only; no Electron, GUI toolkit, primary web engine, SDK agent loop, or generic service dispatcher. The [protocol reference](../docs/NATIVE-TRANSPORT.md) documents the authoritative source envelopes.

## Ownership and privacy

The [Core](../core/README.md), with its `transport` feature, constructs `SecretLaunchUrl` internally and calls `Backend::connect_transport`. A GUI never receives the private ready URL, platform-session token, cookie jar, or arbitrary privileged endpoint access. `SecretLaunchUrl`, `NativeClient`, `Mux`, and transport authority have no Debug/Display/Serialize implementation or credential accessors. A cloneable client is a native worker capability, not serializable GUI state.

Only canonical `http://127.0.0.1:<explicit-port>/?token=...` launch URLs are accepted. Authentication requires the exact 303 `Location: ./` response and exactly one authority-bound `dsh-auth-<SHA256>` cookie with HttpOnly, SameSite=Strict, Path=/, positive Max-Age and future Expires. Domain and HTTP-inapplicable Secure cookies are rejected. No redirects, system proxy, redirected HTML, DNS hostname targets, TLS guest contexts, or external network target is used by this carrier. An explicitly requested model-catalog operation may nevertheless cause the **Host** to contact its configured providers; the native app must not invoke it automatically.

`NativeClient::invalidate` synchronously cancels its generation and removes private cookie/pending-event authority. Core invokes it on stop, Drop and observed Host exit so a stale client cannot hand credentials to a reused server port. `close().await` additionally waits for RPC and WebSocket actor quiescence. The handshake holds an RPC permit until its actor is registered, preventing a close/late-task registration race. One physical mux is allowed per client; logical streams have independent cancellation and late-frame fencing.

## Typed operations

- Session list/create/prompt, model catalog/selection, cancellation ACK, page and projections.
- [Root-only binary ZIP export](<../docs/NATIVE-SESSION-EXPORT.md>) through exact authenticated GET with explicit false descendants, bounded streamed intake, generation cancellation and queue-inclusive deadline. Sensitive non-Clone archive consumes into an owner-selected writer; known classic ZIP structure only, no extraction or full CRC/DEFLATE/content verification. Host live flush can write durable data and root attachments remain included.
- [Bounded raw-byte file staging](<../docs/NATIVE-FILE-UPLOAD.md>) through the exact Session-addressed upload route: 4 MiB bodies/eight generation-owned jobs, strict bounded receipts, tracked cancellation and queue-inclusive deadlines. Cold upload may resume its Agent; staging is not prompt admission or rollback.
- Workspace create/follow; explicit session pin/unpin and archive/restore without activity-stop authority; session follow; projection control baseline/changes.
- `$events` observation and kind/id/generation-checked approval/question results, timed question claim and continued answers.
- Read-only account DTO. Native account UI should use Core's minimal account metadata instead of exposing raw links/sign-in attempts in GUI state.
- Configured plugin inventory, projected nonsecret live-settings descriptors, and one-field revision-checked settings mutations.

Wire contracts retain alpha's `_request`, `agentAvailable`, full-summary added events, fresh follow snapshots with **no resume cursor**, omitted successful void values, and branded opaque IDs. A successful event-result RPC ACK retires only this client's pending delivery: alpha Gateway removes that delivery before settlement and sends Cancel only to the other clients. Neither an ACK nor a returned idempotent no-op proves approval outcome or tool execution. Failed/ambiguous calls retain correlation; external Host Cancel still removes it. Cancellation ACK does not prove idle; Core inspection and its private cancel-generation control have stronger lifecycle semantics.

### Exact decision delivery

[Live-decision ownership](<../docs/NATIVE-DECISION-OWNERSHIP.md>) provides `next_event()` observations carrying an opaque actor-intake `EventDelivery`. Exact typed `*_for` reply methods check that instance through queueing/transmission and revoke only its own acknowledged delivery. Cancel/same-ID reuse cannot make a delayed dequeue, queued legacy future or old reply ACK acquire/remove the new instance. Root/generation closure revokes owners; already transmitted outcomes can remain uncertain. Native worker admission additionally checks worker-issued keys, supported request/answer semantics and single-flight attempts; timed UI is still disabled. Legacy ID methods preserve `.await` use but capture synchronously at invocation, not first future poll. [Authenticated fake-wire race tests](<tests/support/event_delivery.rs>) do not constitute real Agent/Gateway composition or native-input qualification.

### Timed-question claim owner

[Timed-question ownership](<../docs/NATIVE-TIMED-QUESTIONS.md>) defines the acquired `QuestionClaim`: `Mux::hold_question` consumes one strictly validated Host duration item under a queue-inclusive opening timeout. The move-only owner keeps its stream through Host termination independently of reply RPC ACK; normal end means only stream end, and errors remain fixed/sticky. Zero duration is valid, not automatic expiry. `wait_closed` has no renewed TTL or implicit countdown, abandoned reads preserve ownership, and explicit release/Drop is local unsubscribe—not question/Turn cancellation or Host ACK. A first item can already have an end behind it; callers must monitor current delivery/generation/claim liveness before answers. Actual root Agent/call/event authority is an application precondition, not discovered from a session/projection. Native timed/continued controls remain disabled pending independently owned worker/UI integration and real composition testing.

Development API adds `QuestionClaim`, `Mux::hold_question`, `Error::QuestionUnavailable` and strict single-item question-stream validation; existing low-level `question_wait` remains but socket open is not acquisition. [Fake-wire tests](<tests/support/question_claim.rs>) validate protocol ownership, not actual Host/registered-Agent/native UI settlement. The [real alpha wait component tests](<../../deepseek-harness-linux/packages/interaction/user-questions/tests/timed-wait.spec.ts>) separately confirm original-deadline/nonexclusive claims with owned fake timers.

### Registry mutations

`pin_session` / `unpin_session` accept `&SessionRegistryRequest` and return `PinnedSessionsValue`; `archive_session` / `unarchive_session` accept the same request and return `ArchivedSessionsValue`. Requests serialize only `sessionId` under `payload.args.request`. The DTO rejects positional arrays, unknown/duplicate keys and `stopActivity`/`agent`/`signal` fields; it deliberately provides no activity-stop or Agent authority. The exact allowlisted endpoints are `workspace/pinSession`, `workspace/unpinSession`, `workspace/archiveSession`, and `workspace/unarchiveSession`.

Receipts contain the complete **registry-global** identifier lists, not a workspace-local subset or a delta. Vectors retain the Host's order, including most-recent-first pins; object-only receipt decoding never sorts or deduplicates. RPC receipts carry no comparable stream revision: callers must keep [workspace-follow state authoritative](<../docs/NATIVE-SESSION-MANAGEMENT.md#stream-authoritative-state-and-races>) and use a matching ACK to settle the operation, not replace a newer observed set. Archive retains logs and uses the Host's default active-work refusal; restoring does not restore a pin. Admitted errors/timeouts may follow a committed write; no automatic retry, idle-state assertion, deletion or storage manipulation is provided. Queue/epoch/view guards remain the native worker/app's responsibility.

### Plugin inventory and live settings

`plugin_inventory()` calls only `pluginInventory/list`; it projects configured Loader rows and phases, not installation metadata, preset expressions or management authority. `plugin_settings()` calls `settings/describe` and returns typed primitive field descriptors/current nonsecret values. Private wire DTOs resolve the alpha Schemastery `uid`/`refs` graph with recursion/cycle limits; secrets, credential references, sensitive/permission/policy paths, expressions, custom-presentation namespaces, complex nodes and unknown constraints are excluded before publishing public DTOs. Secret-bearing values/defaults, complete config, raw schema, inherited/user layers and arbitrary JSON never reach the native model.

`set_plugin_field(namespace, field, value)` first reads the current live descriptors to verify provider writability, field membership/type and the reviewed revision, then calls `settings/mutate` with one `set` path and mandatory `expectedRevision`. It does not replace a namespace, resend masked values, retry conflicts, invoke credential operations or edit profile files. Fixed `settings-conflict` and `settings-rejected` errors preserve only backend classifications, never messages/details. A rejected provider write may include a persistence/reconciliation failure; callers must not infer that nothing persisted. Unknown/internal errors and lost acknowledgments can follow commit.

Plugin wire results are capped at 1 MiB/32,768 JSON values, 512 inventory rows and 512 total projected fields; paths are at most 16 segments, strings 2,048 UTF-8 bytes, and revisions/integral values fit JavaScript safe integers. Oversized complete results fail instead of becoming editable truncated baselines. The native app owns page/lifecycle/smoke guards, single-flight admission, explicit confirmation and error presentation.

## Bounds and failure behavior

Default complete HTTP result/WS frame cap: **32 MiB**, explicitly configurable up to 128 MiB. JSON recursion is bounded to 64 and values/containers to 100,000. Defaults: inbound queued payload budget 256 KiB, 16 logical streams, 8 concurrent RPCs, 128 pending waterfalls (maximum 1024). JSON application uplink including its full envelope is capped at 262,144 bytes; the separate raw-file operation has its own 4 MiB body bound. Socket sends and HTTP operations are timed/cancellable. Oversized complete snapshots fail explicitly rather than truncating a prefix into a supposedly valid baseline; a caller can request a smaller history window or disclose the limit.

Malformed frames, wrong correlation, sequence gaps, queue overflow, unsupported binary frames, cookie-scope violations and transport closure have closed redacted error codes. Remote messages, details, URLs and payloads are never included in the transport Error. Ping/Pong works without an idle polling timer. Failure invalidates the mux; callers must obtain a fresh snapshot instead of resuming guessed cursors.

## Known limitations and deferred work

- Native UI, visual journal folding, reconnection UX and accessibility belong to the app, not this transport.
- Assistant stream DTOs are typed, but transport itself does not fold semantic attempt/revision/index state; the app must validate it and not infer committed assistant text from partial frames.
- Snapshot retained-record/page contiguity, surface replacement semantics and global safe-integer maxima need stronger boundary tests. Current live durable event cursor progression is checked.
- `AgentId` and `SessionId` now have distinct Rust types (a development API change); question methods and waterfall frames use `AgentId`. Callers must use actual registered Agent/event authority, never derive it from a session ID. [Core discovery](<../docs/NATIVE-AGENT-DISCOVERY.md>) returns registered identity, but native selection/epoch/claim consumers remain incomplete. The raw file-upload route correctly takes SessionId rather than an invented AgentId query.
- [File staging](<../docs/NATIVE-FILE-UPLOAD.md>) has actual SDK/Host/storage qualification; native chooser, worker drafts and prompt receipt binding, image intake/previews/output files remain incomplete. [Test-only actual Host uncertainty gates](<../docs/NATIVE-UPLOAD-UNCERTAINTY.md>) now qualify default-provider ACK-loss/late-disposal persistence and direct receipt transactions/cleanup, not actual prompt admission or all provider/cold-cancel races. Do not advertise attachment parity.
- Uploads independently own queued/active worker cancellation. Other caller-owned HTTP futures must be polled or dropped before awaiting close; retained unpolled acquire/permit futures can still prevent generic shutdown quiescence.
- No arbitrary-browser guest, login guest, Office, terminal, plugin panel, installed updater, or official Linux account infrastructure is provided by this library.
